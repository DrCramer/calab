# Холст v2 — задачи

ADR: [0115 Холст — вторая итерация](../adr/0115-canvas-v2.md) (расширяет [0114](../adr/0114-canvas.md)); v1 — [canvas-v1-tasks.md](canvas-v1-tasks.md). Ветка интеграции — `feat/canvas`; задачи — в своих worktree и ветках, лид мержит в `feat/canvas`.

Решение владельца (20.10): делаем волны 1–5; рисование от руки и картинки откладываем.

**Исполнение — строго по одной сессии за раз.** Параллельные сессии перегревали процессор владельца (load average 78). Правила нагрузки для каждой сессии: все тяжёлые команды через `nice -n 19`; в цикле только тесты затронутых файлов (`vitest run <файлы> --maxWorkers=2`); полные `pnpm -r typecheck`, `pnpm -r lint`, `pnpm -F @calaba/desktop test` (и для серверных волн `golangci-lint` + интеграционные тесты пакетов) — по одному разу в конце и последовательно; никаких фоновых процессов после себя; стенд владельца (БД `calaba_demo`, Redis DB 5, порты 3090/5190) не трогать.

Порядок: V1a → V1b → V2 → V5 (клиентские, дёшево по риску) → V3 → V3r → V4 → V4r → V6 → R4. Независимое ревью (V3r, V4r и вся ветка `feat/canvas`) проводит владелец перед PR: лид не останавливается после V3/V4, идёт по волнам до конца и передаёт ветку целиком с перечнем мест повышенного риска (права, анонимный сокет, уведомления, миграции). Волны 4–5а можно переставить по желанию владельца (V3 и V4 независимы друг от друга, обе после клиентских).
