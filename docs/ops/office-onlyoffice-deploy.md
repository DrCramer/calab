# Методичка для девопса: редактор документов ONLYOFFICE в проде

Для чего: открывать и править xlsx, docx, pptx (и odt, ods, odp, rtf, csv, txt) из Диска в окне Calab. Решение — ADR-0143. Здесь только то, что нужно, чтобы поднять и поддерживать сервис в кластере. Код и логику читать не нужно.

Пометки в тексте: **[замерено]** — померили на пробном стенде 28.10.2026 (образ 10.0.0.1, один открытый документ), **[док]** — из документации ONLYOFFICE, **[проверить]** — не проверено, сделать при выкатке.

## 1. Что поднимаем

Один новый сервис и немного настроек вокруг него. Ни базы, ни очереди, ни хранилища файлов для него отдельно заводить не нужно: он работает с файлами, которые ему отдаёт API Calab, и после сохранения возвращает их обратно.

| Что | Сколько | Зачем |
|---|---|---|
| **ONLYOFFICE Document Server** (`onlyoffice/documentserver`) | один под, `replicas: 1`, `strategy: Recreate` | сам редактор |
| Ingress с TLS `docs.<домен>` | одна запись | браузер и приложение грузят редактор отсюда |
| Secret с `JWT_SECRET` | один | общий ключ подписи между API Calab и Document Server |
| ConfigMap со страницей-обёрткой и темой | один | `infra/office/calab-editor.html` и `calab-editor.js` → `/var/www/onlyoffice/documentserver/web-apps/apps/calab/`; по желанию `infra/office/themes/theme-calab-dark.json` → `…/web-apps/apps/common/main/resources/themes/`; только на чтение |
| PVC | два тома (п. 4) | кэш и несохранённые сессии переживают перезапуск |
| NetworkPolicy | одна | кто к кому ходит (п. 3) |
| Правка env у API Calab | 10 переменных `OFFICE_*` (п. 5) | включить и подключить |

Меняется только API (env) и появляется новый под. Веб-клиент и образы приложений пересобирать отдельно не нужно: клиент приходит обычным релизом.

**Важно: одна копия.** Бесплатная сборка (Community) не масштабируется на несколько подов: две копии разделят сессии совместной правки и будут портить документы. Поэтому `replicas: 1`, а при выкатке допустим простой в несколько минут. Пока под перезапускается, Диск и всё остальное работает, не открывается только редактор.

## 2. Версия и вес

- Образ: `onlyoffice/documentserver`, пробный стенд работал на `10.0.0.1` **[замерено]**. Закрепить версию по digest, не по `latest`. Обновлять осознанно (п. 8).
- На диск узла: **3,14 ГБ** распакованный образ, 0,94 ГБ в сжатом виде **[замерено]**. Узлу нужно минимум 5 ГБ свободного места под образ и слои.
- Память: **≈ 370 МиБ в простое, 370–414 МиБ с одним открытым документом** **[замерено]**. Нагрузку с десятками одновременных документов не мерили **[проверить]**: она растёт с числом открытых документов и с конвертациями.
- Процессор: около нуля в простое, 1 ядро на пике открытия **[замерено на одном документе]**.
- Рекомендация для старта (наша, не измеренная): `requests: 1 GiB / 500m`, `limits: 4 GiB / 2 CPU`. После первой недели посмотреть реальные цифры и поправить. В ADR стоят заявки с запасом (2 GiB / 1 CPU) «до замеров»: можно начать с них.
- Время старта пода не замеряли **[проверить]**. Поставить `startupProbe` с запасом (до 5 минут) и по факту уменьшить.
- Проверка живости: `GET /healthcheck` должен вернуть `true` **[док]**.
- Порт в контейнере: 80 (за ingress с TLS).

## 3. Как всё соединяется

```
Браузер / Calab desktop
   │  1) GET https://<app>/api/office/capabilities, /config      (обычный API Calab, с нашим токеном)
   │  2) iframe на  https://docs.<домен>/web-apps/apps/calab/calab-editor.html
   ▼
Document Server  ──(внутри кластера)──►  API Calab
   │     GET  /api/office/file/{токен}       скачать файл (ссылка живёт 5 минут)
   │     POST /api/office/callback/{токен}   сохранить: статус 2 или 6
   ▲
API Calab  ──(внутри кластера)──►  Document Server
         POST /converter   (сохранить как, старые doc/xls/ppt)
         POST /command     (закрыть сессию, если у человека отобрали доступ)
         GET  /cache/...   (забрать сохранённый файл)
```

Три направления трафика, и все три должны работать:

1. **Браузер → Document Server** (публичный): через ingress `docs.<домен>`. Загружается JS редактора и страница-обёртка.
2. **Document Server → API Calab** (внутри кластера): забирает файл и шлёт сохранение. Адрес задаётся `OFFICE_API_URL`, это внутренний Service API.
3. **API Calab → Document Server** (внутри кластера): адрес `OFFICE_DOCS_INTERNAL_URL`, это внутренний Service Document Server.

**Ловушка № 1: адреса из частной сети.** По умолчанию Document Server отказывается ходить на внутренние IP (защита от SSRF). Адрес Service API в кластере как раз внутренний. Поэтому у контейнера Document Server нужен `ALLOW_PRIVATE_IP_ADDRESS=true` **[док]**. Взамен ограничиваем его NetworkPolicy (ниже): ходить ему можно только к API.

**Ловушка № 2: frame-ancestors.** Редактор встраивается в iframe Calab. Ingress Document Server должен отдавать заголовок:
`Content-Security-Policy: frame-ancestors 'self' <все публичные адреса приложения>`.
Публичных адресов несколько (основной домен и алиас из `docs/06`, веб-версия). Приложение для компьютера (Electron) загружается из `file:`, и этот случай надо проверить отдельно **[проверить]**: если CSP не пускает `file:`, редактор в приложении будет пустой рамкой. Тогда либо убрать `frame-ancestors` и оставить защиту только JWT и NetworkPolicy, либо менять схему загрузки приложения. Решить на первом тесте. Сам Electron пускает в рамку только origin, который ему назвал API (`GET /api/office/capabilities` → `docs_url`, то есть `OFFICE_DOCS_URL`), и только страницу `/web-apps/apps/calab/calab-editor.html` на нём: `OFFICE_DOCS_URL` должен совпадать с адресом ingress точно (схема `https`, хост, порт).

**Ловушка № 3: закрыть служебные пути редактора.** На публичном ingress Document Server (`docs.<домен>`) пользователю нужны только статика и страницы редактора. Служебные пути закрыть для интернета (отвечать 403 или 404): `/converter`, `/command`, `/ConvertService.ashx`, `/coauthoring/CommandService.ashx`, `/example`, `/info`. Их вызывает только API Calab внутри кластера по `OFFICE_DOCS_INTERNAL_URL`. Иначе подписанный запрос может заставить конвертер ходить по внутренней сети.

**NetworkPolicy:**
- Document Server → исходящий только к API Calab и DNS. Больше никуда.
- Document Server ← входящий от ingress-контроллера и от API Calab.
- API Calab ← входящий от Document Server (маршруты `/api/office/file` и `/api/office/callback`). Их снаружи открывать не нужно: если ingress API это умеет, закрыть эти два пути для интернета.

## 4. Тома

| Путь в контейнере | Что там | Размер на старт |
|---|---|---|
| `/var/lib/onlyoffice` | кэш документов и несохранённые сессии правки | 10 ГиБ, следить за заполнением |
| `/var/www/onlyoffice/Data` | служебные данные | 5 ГиБ |

Источник истины для файлов — Диск Calab, а не Document Server: после сохранения файл лежит в Диске с версией. Потеря томов Document Server теряет только несохранённую правку открытых в этот момент документов. Резервные копии этих томов можно не делать. Внутри образа есть встроенные PostgreSQL, Redis и RabbitMQ **[док]**; нужен ли отдельный том под встроенную базу, надо посмотреть в манифесте образа **[проверить]**.

## 5. Переменные

### 5.1. API Calab (в Vault)

В прод они попадают через Vault `kv/app/calab` → `timenote/calab-env-sync` → Secret `calab-env` (см. `docs/06`). **Каждая строка должна быть в Vault**: reconciler удаляет из Secret всё, чего нет в Vault. После правки дождаться синхронизации и сделать rollout API.

| Переменная | Значение в проде | Секрет? |
|---|---|---|
| `OFFICE_ENABLED` | `true` (включать последним, п. 6) | нет |
| `OFFICE_DOCS_URL` | `https://docs.<домен>` | нет |
| `OFFICE_DOCS_INTERNAL_URL` | `http://<service-document-server>.<ns>.svc` | нет |
| `OFFICE_API_URL` | `http://<service-api>.<ns>.svc` (внутренний адрес API) | нет |
| `OFFICE_JWT_SECRET` | случайные ≥ 32 байта, **отдельный секрет**: не равен `JWT_SECRET` самого API Calab (иначе API не запустится) | **да** |
| `OFFICE_THEME_DARK` / `OFFICE_THEME_LIGHT` | по умолчанию `default-dark` / `default-light`; для тёмной можно `theme-calab-dark` (цвета Calab, файл темы смонтирован, п. 1). Светлой темы Calab нет: `default-light` | нет |
| `OFFICE_FILE_URL_TTL` | `5m` | нет |
| `OFFICE_MAX_SIZE_MB` | `100` | нет |
| `OFFICE_SESSION_TTL` | `24h` | нет |

Выключенный флаг (`OFFICE_ENABLED` не задан или `false`) полностью прячет редактор: маршруты `/api/office/*` и создание файлов отвечают 404, «Открыть» в редакторе и пункты «Создать → Документ / Таблица / Презентация» в приложении не показываются (приложение спрашивает флаг у API при каждом подключении). Это быстрый откат.

### 5.2. Document Server (в Secret/ConfigMap пода)

| Переменная | Значение | Зачем |
|---|---|---|
| `JWT_ENABLED` | `true` | подпись всех запросов |
| `JWT_SECRET` | **тот же**, что `OFFICE_JWT_SECRET` | общий ключ (держать в одном месте и ссылаться в обоих) |
| `JWT_HEADER` | `Authorization` | заголовок с токеном |
| `JWT_IN_BODY` | `true` допустимо | API принимает оба варианта |
| `ALLOW_PRIVATE_IP_ADDRESS` | `true` | см. ловушку № 1 |
| `WOPI_ENABLED` | `false` | не нужен |
| `PLUGINS_ENABLED` | `false` | не нужны |

Без явного `JWT_SECRET` образ сам придумывает случайный при каждом старте, и API перестанет с ним договариваться. Всегда задавать явно.

### 5.3. Конфиг Document Server

Один параметр: `services.CoAuthoring.autoAssembly` с `enable: true`, `interval: 5m`. Тогда версия файла попадает в Диск не реже раза в 5 минут, пока идёт правка, а не только при закрытии документа **[док; проверить на выкатке]**.

## 6. Порядок выкатки

1. Сделать случайный секрет не короче 32 байт. Положить в Vault (`OFFICE_JWT_SECRET`) и в Secret пода Document Server.
2. Применить манифесты: Secret, ConfigMap, PVC, Deployment, Service, Ingress `docs.<домен>`, NetworkPolicy. Подождать `Ready`.
3. Проверить, что `https://docs.<домен>/healthcheck` отвечает `true`, а в ответе есть заголовок `frame-ancestors`.
4. Проверить из пода API: `curl http://<service-document-server>.<ns>.svc/healthcheck` и из пода Document Server: `curl http://<service-api>.<ns>.svc/` (должно доходить).
5. Добавить в Vault 10 переменных `OFFICE_*` (п. 5.1), **но `OFFICE_ENABLED` пока `false`**. Дождаться синхронизации, rollout API.
6. Включить `OFFICE_ENABLED=true`, дождаться rollout.
7. Приёмка (п. 7).
8. Сообщить клиентам, что функция работает. Нужна версия приложения, в которой есть клиентская часть (выходит обычным релизом). Приложение подхватывает включение при следующем подключении к серверу, перезапуск не нужен.

**Откат:** `OFFICE_ENABLED=false` и rollout API: редактор исчезает, остальное работает. Под Document Server можно остановить, данные не пострадают.

## 7. Приёмка после выкатки

1. В приложении открыть xlsx из Диска: редактор показался внутри окна, тема совпадает с приложением.
2. Изменить ячейку, дождаться «Изменения сохранены». В «Истории» файла появилась запись, у файла новая версия, `sha256` и размер в API поменялись.
3. Открыть один и тот же файл с двух аккаунтов: оба видят правки друг друга.
4. Пользователь с правом только на просмотр: файл открывается только для чтения.
5. Открыть docx, pptx и старый doc (для doc должно предложить «Сохранить как .docx»).
6. В Диске «Создать → Документ»: появился «Новый документ.docx» и сразу открылся в редакторе; он же открывается в Word / LibreOffice после скачивания.
7. Вложение xlsx в чате: открывается только для просмотра, «Сохранить в Диск» делает копию, которая правится.
8. Закрыть вкладку при несохранённой правке: приложение спрашивает.
9. Проверить Electron-приложение отдельно: редактор не должен быть пустой рамкой (см. ловушку № 2).
10. В логах API есть строки `office: open|callback|saved|created`; в них нет содержимого файлов. 5xx на `/api/office/callback` нет.

## 8. Эксплуатация

- **Логи.** API: строки `office: open|callback|saved|drop|converted|created` (id пользователя, элемента, ключ, статус, размер, sha256; содержимое не пишется). Document Server: логи контейнера, при проблемах `/var/log/onlyoffice`.
- **Что смотреть:** перезапуски пода, память (рост при множестве документов), заполнение томов, 5xx на `/api/office/callback` и `/file`, `healthcheck`.
- **Обновление версии.** Идёт на пробном стенде, не на проде в первую очередь: после обновления прогнать приёмку (п. 7) и xlsx из реальных файлов команды. Образ — по digest. Следить за уведомлениями безопасности ONLYOFFICE, версию держать свежей.
- **Отказ.** Один под: если он лёг, не открывается только редактор. Файлы в Диске целы, последняя версия в Диске. Несохранённая правка за последние минуты может потеряться.
- **Лимиты в API:** конфиг и «Создать» вместе 30 запросов/мин на пользователя, «сохранить как» 5/мин, запросы Document Server 120/мин на файл. Размер файла до `OFFICE_MAX_SIZE_MB`, версий до 50 на файл.
- **Хранилище файлов.** Если на проде `STORAGE_DRIVER=s3`, сохранение пишет новую версию тем же путём, что и обычная загрузка. Прогнать приёмку именно на S3 **[проверить]**.

## 9. Безопасность (чек-лист)

- Секрет ≥ 32 байт, лежит только в Vault и в Secret. В логах, манифестах и репозитории его нет.
- NetworkPolicy стоит, исходящий трафик Document Server ограничен API и DNS. Без неё `ALLOW_PRIVATE_IP_ADDRESS=true` опасен: подписанный запрос к `/converter` дойдёт до чего угодно в кластере.
- Служебные пути (`/converter`, `/command`, `/ConvertService.ashx`, `/coauthoring/CommandService.ashx`, `/example`, `/info`) на публичном ingress закрыты (п. 3, ловушка № 3).
- `OFFICE_JWT_SECRET` не равен `JWT_SECRET` API.
- `ALLOW_PRIVATE_IP_ADDRESS=true` оправдано только вместе с NetworkPolicy.
- `frame-ancestors` перечисляет только наши адреса. Встроить редактор в чужой сайт нельзя.
- `WOPI_ENABLED=false`, `PLUGINS_ENABLED=false`.
- Ссылка на файл живёт 5 минут и привязана к одной версии. Callback принимает URL только с нашего Document Server. Подробный разбор угроз — раздел 9 ADR-0143 и результат независимого ревью.
- Логотип ONLYOFFICE на месте. Это условие лицензии (AGPLv3 с дополнительными условиями), его не убирать. Бренд заменяется только в коммерческой редакции.

## 10. Что пока не проверено

- Нагрузка: десятки одновременных документов и конвертаций. Память и CPU подбирать по факту.
- Электрон: работает ли встраивание при загрузке приложения из `file:`.
- S3-хранилище на проде.
- Как настоящий Document Server 10 ведёт себя при переподключении с конфигом старше 12 часов (срок жизни конфига — 12 ч): проверить на первом долгом сеансе.
- Кластер Valkey: скрипты сессий используют два ключа и в режиме Valkey Cluster упадут. На одиночном экземпляре (как сейчас) всё работает.
- Миграция `00133` на время проверки берёт жёсткую блокировку таблицы `disk_activity`: выкатывать в спокойное время.
- Время старта пода и нужен ли том под встроенную базу образа.
- Формат даты в русском интерфейсе (`01,07,2026` вместо `01.07.2026`): конфиг теперь передаёт `editorConfig.region` по языку приложения (`ru-RU`), проверить на настоящем «График отпусков 2026.xlsx».
- Условное форматирование и проверка данных в xlsx после правки в редакторе переписываются в расширение, которое openpyxl не читает. Боту, который пересохраняет такой файл через openpyxl, правила пропадут. Обговорить с владельцами таких ботов.
- Язык проверки орфографии: в документах с языком en-US (так их пишет python-docx по умолчанию) русский текст подчёркивается — редактор проверяет текст по языку, записанному в документе. Новые файлы из «Создать» получают язык приложения. Для старых — язык текста в строке состояния редактора или язык в боте, который пишет файл.
