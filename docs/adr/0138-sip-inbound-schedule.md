# ADR-0138: Расписание входящих — рабочие часы точки входа и «нерабочее время →» (2026-10-27)

**Статус: принято (27.10), сервер реализован (ветка `feat/sip-schedule`); интерфейс — этап T5 раздела «Телефония»
([ADR-0137](0137-telephony-section.md)).** Расширяет [ADR-0117](0117-sip-inbound-ivr.md) §4 (точка входа, машина
состояний), использует цели маршрутов ADR-0117/[ADR-0124](0124-sip-group-fallback.md) и производственный календарь
[ADR-0136](0136-calendar-workdays-repeat.md).

## Контекст

Владелец (27.10): входящий в нерабочее время должен сразу уходить на другую цель — AI-бота «Гром» (номер бота), другое
меню, группу или «положить трубку с сообщением», — а не звонить операторам до таймаута переадресации. Бот, получивший
такой звонок, должен понимать, почему он ему достался: «нерабочее время» или «операторы заняты / не ответили».

## Решение

1. **Где живёт.** Точка входа у пространства одна (`sip_accounts.inbound_*`, номер пространства), поэтому расписание —
   в той же строке (миграция `00031_sip_schedule.sql`): `schedule_enabled`, `schedule_tz` (IANA, по умолчанию
   `Europe/Moscow`), `schedule_hours jsonb` — интервалы `{weekday 1..7, start 0..1439, end 1..1440}`,
   `schedule_holidays` (`''` / `ru`), действие `off_hours_kind` + по FK-колонке на вид (как у точки входа, `ON DELETE
   SET NULL` только своей колонки — удалённая цель кладёт трубку) и `off_hours_notice_file_id/_ms` — сообщение. Когда
   номеров станет несколько, расписание переедет вместе с точкой входа.
2. **Часы.** Несколько интервалов в день (≤ 6), конец меньше начала — интервал до следующего дня (ночная смена
   22:00–02:00; воскресная — в понедельник), `1440` — полночь. Пересечения (с учётом перехода через полночь и с
   воскресенья на понедельник) — `422 hours`; включённое расписание без часов — `422`. Конец интервала — уже нерабочее
   время.
3. **Производственный календарь РФ** — та же таблица, что у встреч: она вынесена в лист-пакет `internal/prodcal`
   (`IsWorkday`, `ChangesRU`), календарь встреч и телефония пользуются им, таблица не дублируется. Будний выходной
   (праздник, перенос) — без часов; рабочая суббота/воскресенье — по своим часам, а без них — по часам первого дня
   пн–пт, у которого они есть (обычно понедельник). Ночная смена, начатая накануне праздника, доходит до утра.
   Год вне таблицы — как без календаря.
4. **Когда проверяется.** Один раз — когда звонок пришёл, перед точкой входа (`InCall.EnterEntry`); звонок, пришедший в
   рабочее время, свой маршрут не меняет, когда часы кончились. Вне часов: шаг журнала `schedule` (reason
   `off_hours`, цель — действие), затем сообщение (если загружено, `notice` с reason `off_hours`; кнопки не
   принимаются) и действие: меню, номер человека/бота, группа — обычный `Enter`; «положить трубку» — конец звонка с
   `SipCall.reason = "off_hours"`. Такой звонок считается пропущенным (`missed`, как «положить трубку» в меню) — его
   видно в журнале, чтобы перезвонить; бейджи не горят — он никому не звонил.
5. **Что видит бот (и человек).** В `SipCall` входящего (`SIP_INBOUND_RING`, `SIP_CALL_UPDATE`) — два флага:
   `off_hours` — звонок пришёл в нерабочее время и идёт по маршруту расписания (на весь звонок); `via_fallback` —
   текущий маршрут достигнут переадресацией группы (ADR-0124: таймаут, все заняты, все отклонили; в том числе сразу —
   когда звонить в группе некому). Оба ложны — обычный маршрут; оба — нерабочее время, где группа ушла в
   переадресацию. Флаги берутся из состояния машины (Valkey) в момент события, в строку звонка не пишутся — история в
   событиях журнала. `via` (имя меню/группы) не перегружаем: это имя, а не причина. Перевод (ADR-0132) сбрасывает
   `via_fallback`.
6. **API.** `PUT /api/workspaces/{id}/sip/schedule {schedule, notice_source_file_id?}` — `MANAGE_INTEGRATIONS`, тариф
   телефонии, сначала сохранённый провайдер (`409`); заменяет расписание целиком; сообщение — как приглашение меню
   (своя загрузка, MP3/Ogg/WAV ≤ 3 мин, `""` — удалить). Ответ и `GET …/sip` — `SipSettings.schedule`. Файл сообщения
   — «приглашение» для воркера, скачивания и сборщика сирот (`GetSipPromptFile`, `IsSipPromptFile`, orphan-запрос).
   Боты — так же (ADR-0109).

## Отвергнуто

- **Расписание на меню/группе.** Владельцу нужна развилка до первого шага; расписание на объектах размножает настройку и
  спорит с «нажал кнопку в 17:59».
- **Переоценка на каждом шаге.** Звонок, принятый в рабочее время, не должен посреди очереди уйти боту в 18:00.
- **Причина в `via`.** `via` — имя для модалки и журнала; смешивание сломало бы клиентов, показывающих «через …».
- **Свои часы для перенесённой субботы из постановления.** Таблица ADR-0136 не хранит, какой день перенесён; часы
  первого рабочего дня недели — понятное правило, сокращённые предпраздничные дни не учитываются (как у встреч).

## Последствия

- Новый вид события журнала `SIP_CALL_EVENT_KIND_SCHEDULE` и причина `off_hours`; клиент (T5) показывает «Нерабочее
  время → Гром».
- Документация бота (лендинг, «Боты и телефония») описывает `offHours` / `viaFallback`.
- Нет UI до T5: настройка — через API (бот или curl).
