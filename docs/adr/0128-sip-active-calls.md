# ADR-0128: Активные звонки станции — `GET …/sip/calls` и `SIP_CALLS_CHANGED` (2026-10-23)

**Статус: принято (23.10, CBF-77).** Дополняет [ADR-0117](0117-sip-inbound-ivr.md) (входящие, машина
состояний в Valkey) и [ADR-0046](0046-sip-telephony.md) (журнал `sip_calls`).

## Контекст

Владелец (23.10) просит вкладку «Активные звонки» в настройках телефонии: что идёт прямо сейчас — кто
звонит, где звонок (меню, звонит группе, с кем соединён), сколько длится. Журнал (`GET …/calls`,
`VIEW_JOURNALS`) отдаёт строки `sip_calls`, но шага входящего звонка в нём нет (он только в Valkey,
`sipin:<id>`), а живые события входящего (`SIP_INBOUND_RING`, `SIP_CALL_UPDATE`) идут лишь тем, кому
звонок звонит, — админ, который смотрит станцию, их не получает.

## Решение

1. **`GET /api/workspaces/{id}/sip/calls`** (`MANAGE_INTEGRATIONS`, как настройки телефонии; не гость; боты
   тоже — «закрыто от имени») → `ListSipActiveCallsResponse { calls: SipActiveCall[] }`: живые строки
   `sip_calls` пространства (обоих направлений, начаты < 3 ч назад, ≤ 100, старые сначала). Входящие —
   только с живым состоянием в Valkey (один `MGET`), шаг из него: `MENU` (+ id и имя меню), `RINGING`
   (+ группа, `ringing_user_ids`), `CONNECTED` (`answered_by`). Исходящие — `DIALING` / `CONNECTED`, звонки
   комнат, которых вызывающий не видит, не входят (как в журнале).
2. **Номер**: полностью — при `VIEW_JOURNALS` (журнал и так его показывает), иначе маской
   `+7916*****67` и `number_masked = true`.
3. **`SIP_CALLS_CHANGED { workspace_id }`** — новое событие без деталей в канал пространства; gateway
   доставляет его только сессиям с `MANAGE_INTEGRATIONS` (не гостям, не ботам). Публикуется на каждом
   видимом шаге входящего (после сохранения состояния) и на каждом изменении исходящего. Клиент
   перечитывает список, только пока открыта вкладка и окно видно (иначе лишь помечает устаревшим).

## Почему не иначе

- Переиспользовать `SIP_CALL_UPDATE` для админов — меняет смысл события для клиентов (плитка линии в
  комнате, модалка входящего) и потребовало бы шага в `SipCall`. Тонкий «пинг» дешевле и не несёт номеров.
- Опрос раз в N секунд — задержка и работа, даже когда звонков нет; событие приходит, только когда
  что-то изменилось.

## Последствия

- Новый маршрут классифицирован в `identityroutes.go` (`scopeWorkspace`) и `botroutes.go` (чтение),
  событие — в `eventScope`; справочник бота (`_routes.json`, gateway-events) обновлён.
- Таймер длительности — на клиенте от `started_at` / `answered_at` (листовой компонент), сервер не шлёт
  тики.
