## Контекст

Владелец (27.10): «Вкладка „Телефония“ на левом рейле, видна только если телефония подключена. В ней:
(1) контакты — чтобы при звонке был виден не номер, а компания или ФИО; (2) позвонить оттуда; (3) журнал —
кто кому звонил, сколько говорили; у входящих — сколько ждал, что нажимал в автоответе, на кого попал, кто
кого переводил — весь журнал в удобном виде. Ориентир — «Телефон» на iPhone (Недавние / Контакты / Клавиши) и
популярные АТС (Mango Office, Zadarma, UIS, Битрикс24, 3CX, FreePBX CDR). Настройки телефонии (группы,
номера, IVR и т. д.) — тоже туда, пункт «Телефония» из настроек убрать совсем». Координатор (27.10):
**главное — телефон**: удобно одной рукой, действия внизу, паттерны «Телефона» iPhone.

### Что есть сегодня (по коду, 27.10)

- **Журнал** — одна строка `sip_calls` на звонок (миграции 00051, 00111, 00112): номер, направление,
  статус, причина, `started_at/answered_at/ended_at`, `started_by`, `answered_by`, `ended_by`,
  `ringing_user_ids` (кто звонит *сейчас*), `via` и `route` — **строка ≤ 500 символов** вида
  `menu:<id> → key:2 → notice → group:<id> → transfer:ext:<id> → transfer:answered`, **без времени**, без
  имён (id удалённого меню ничего не скажет), обрезается на длинных звонках. Пишется в
  `sip.Service.apply` (`internal/sip/inbound.go`) по `Effects.Changed`; метки ставит чистая машина
  `InCall.step()` (`machine.go`, `transfer.go`, `dial.go`). Читается `GET /api/workspaces/{id}/calls`
  (`VIEW_JOURNALS`, 100 на страницу) — таблица во вкладке настроек.
- **Чего машина не сохраняет**, хотя знает в момент перехода: время каждого шага (`Env.Now` есть); кому
  звонили и чем кончился звонок каждому (`Effects.Rings/Stopped`, `InCall.Rang`, `Declined` — только в
  Valkey, после звонка исчезают); имена меню/групп на момент звонка; переадресация группы как событие;
  попытки меню и «нет ввода»; исход записи (живёт отдельно в `sip_call_recordings`). Исходящие
  (`calls.go`) пишут только статусы строки.
- **«Удержание» (hold) и «парковка» звонка** в смысле АТС не существуют: ADR-0133 паркует *голосовую
  комнату участника*, не звонок; в журнал это не попадает и не должно.
- **Исходящий звонок есть только из голосовой комнаты** (ADR-0046): `POST /api/rooms/{id}/calls`, линия
  входит в LiveKit-комнату комнаты, звонящий должен быть в её звонке; один живой звонок на комнату; 20 в час
  на пространство; Caller ID — `sip_accounts.caller_id`. «Личного» звонка (я ↔ абонент) нет.
- **Принятый входящий** — уже личный звонок: своя комната `sipin_*`, `voice.join(..., {call: true})`,
  пауза голосовой комнаты (ADR-0133), островок/полоса звонка, перевод (ADR-0132). Это готовый образец
  для исходящего из вкладки.
- **Контактов нет.** Модалка входящего показывает номер и `via`. `User.phone` сотрудников (ADR-0077) с
  номерами звонков не сопоставляется.
- **Настройки** — `features/workspace/TelephonyTab.tsx` (+ `TelephonyExchange.tsx` 1680 строк,
  `TelephonyCalls.tsx`, `TelephonyRecording.tsx`) в окне настроек пространства, `Choice` «Активные звонки ·
  Номера · Группы · IVR · Настройки»; на телефоне — те же карточки и **таблица журнала** в 390 px.
- **Права**: настройки — `MANAGE_INTEGRATIONS`, журнал — `VIEW_JOURNALS`, звонить — `PLACE_CALLS`
  (бит 24; пространство и комната), активные звонки — `MANAGE_INTEGRATIONS`. Телефония — только Business
  и on-prem (`telephony_disabled`).

## Решение

### 1. Журнал: звонок + упорядоченные события

**Модель** (миграция T1, следующая свободная — `00029_sip_call_journal.sql` на 27.10):

- `sip_calls` остаётся строкой звонка (итог, сводка, быстрые фильтры) и получает:
  - `origin text NOT NULL CHECK (origin IN ('room','personal','inbound','test'))` — откуда звонок
    (`room_id NULL` сегодня означает и проверку подключения, и удалённую комнату — различаем явно).
    Заполнение старых строк: `in` → `inbound`; `room_id` есть → `room`; иначе номер = `caller_id`
    аккаунта → `test`, остальное → `room` (комната удалена). Без значения по умолчанию: каждая вставка
    называет `origin` сама.
  - `peer_e164 text NOT NULL DEFAULT ''` — номер внешней стороны в E.164 (`sip.NormalizeNumber`; не
    нормализуется — пусто, `number` хранит как прислано). Индекс `(workspace_id, peer_e164)` — поиск по
    номеру и сопоставление с контактами. Старые строки — копия `number`, если он уже E.164.
  - `missed boolean` — пропущенный (определение ниже), ставится в момент конца звонка (той же
    транзакцией, что событие `ENDED`); старые строки — по `route`/`reason`. Хранится, чтобы фильтр
    «Пропущенные» и бейдж шли по индексу, а не по событиям.
  - индекс `(workspace_id, started_at DESC, id DESC)` — страницы журнала.
  - `route` и `via` остаются (старые клиенты, `SipCall.route`); новые клиенты их не читают. Убрать — не
    раньше чем через два релиза, отдельной миграцией.
- `sip_call_events (call_id uuid REFERENCES sip_calls ON DELETE CASCADE, seq int CHECK (seq ≥ 1),
  at timestamptz, kind text CHECK (…), user_id uuid NULL REFERENCES users ON DELETE SET NULL,
  peer_user_id uuid NULL … SET NULL, target_kind text NULL, target_id uuid NULL, target_name text ≤ 64,
  digits text ≤ 16, reason text ≤ 64, PRIMARY KEY (call_id, seq))`, читается в порядке `(at, seq)`. **Без FK на цели** (`target_id` —
  история: меню и группы удаляются); имя цели — **снимок на момент звонка** (`target_name`), чтобы журнал
  читался и после переименования/удаления.
- `sip_call_parties (call_id … CASCADE, user_id … CASCADE, workspace_id, started_at, placed bool, rang
  bool, answered bool, transferred bool, PRIMARY KEY (call_id, user_id))`, индекс
  `(workspace_id, user_id, started_at DESC, call_id DESC)` — «мои звонки» и «мои пропущенные» без
  сканирования событий. Пишется в той же транзакции, что события (upsert с OR флагов); старые звонки —
  `started_by` (placed) и `answered_by` (answered) при миграции.
- `sip_accounts.retention_months smallint NOT NULL DEFAULT 12 CHECK (IN (1,3,6,12,24,36))` — срок
  хранения журнала и (с T2) контактов (владелец 27.10, «Хранение» ниже); `sip_accounts.out_per_hour int
  DEFAULT 120`, `out_per_user_hour int DEFAULT 30` (1..1000) — лимиты исходящих («Лимиты», §3).
  `workspace_members.sip_seen_at timestamptz NOT NULL DEFAULT now()` — когда я последний раз смотрел
  «Недавние» (счётчик пропущенных на рейле); при выкатке — `now()` у всех, чтобы старые звонки не зажгли
  бейдж.

**Виды событий** (`SipCallEventKind`; `target_*` — меню/группа/номер/участник, `user_id` — сотрудник шага):

| Событие | Когда (кто эмитит) | Поля |
|---|---|---|
| `STARTED` | вход линии (`InboundJoined`) / создание исходящего (`calls.go`, `outbound.go`) | вх.: `digits` = номер компании (trunk), `reason` = `direct`/`register`; исх.: `user_id` звонящий, `target` = комната |
| `MENU` | `Enter`/`playMenu` (каждый проигрыш) | `target` меню, `digits` = номер попытки |
| `KEY` | `press` | `digits` = кнопка |
| `DIALED` | `dial` (ADR-0129) | `digits` набранное, `reason` = `found`/`not_found` |
| `NO_INPUT` | `noInput` | — |
| `NOTICE` | `noticeFirst` (ADR-0131) | `target` меню |
| `GROUP` | `ring` по группе | `target` группа, `reason` = `ring_all`/`round_robin` |
| `RING` | `ringAll`/`ringAt` (каждому, кому начали звонить) | `user_id`, `target` группа или пусто |
| `RING_END` | `stopRinging`/`Decline`/таймаут участника | `user_id`, `reason` = `no_answer`/`declined`/`answered_elsewhere`/`fallback`/`caller_left`/`busy` |
| `FALLBACK` | `failRing` по переадресации (ADR-0124) | `target` куда, `reason` = `timeout`/`nobody`/`declined` |
| `ANSWERED` | `Answer` / ACTIVE исходящего | `user_id` (у исходящего — абонент: пусто) |
| `TRANSFER` | `Transfer` (ADR-0132) | `user_id` кто переводит, `peer_user_id`/`target` кому |
| `TRANSFER_END` | `transferTaken`/`transferBack`/`CancelTransfer` | `reason` = `answered`/`no_answer`/`declined`/`cancelled`/`not_connected` |
| `DIALING`, `PROVIDER_RINGING` | исходящие: старт `CreateSIPParticipant`, `sip.callStatus = ringing` | — |
| `RECORDING` | `CallRecorder` (ADR-0131) | `reason` = `started`/`stored`/`failed_<причина>` |
| `ENDED` | финал | `reason` (коды `SipCall.reason`), `user_id` = кто положил (сотрудник) или пусто (абонент/система) |

**Захват и идемпотентность.**
- Входящие: чистая машина вместо `step(label)` вызывает `c.log(e, Event{…})` — событие с `At = e.Now` и
  `Seq = ++c.Seq` (новое поле `InCall.Seq`) кладётся в `Effects.Events`; `step` продолжает вести `Route`
  для совместимости. Точки — те же места, где сегодня ставится метка, плюс `ringAll`/`ringAt`,
  `stopRinging`, `Decline`, `Answer`, `failRing`, `transfer*`. `Service.apply` пишет
  `Effects.Events` и участников **одной транзакцией вместе со строкой `sip_calls`** (`INSERT … ON
  CONFLICT (call_id, seq) DO NOTHING`) **до** сохранения состояния в Valkey: повтор перехода после сбоя
  даст те же `seq` и ничего не задвоит; потеря состояния после записи — максимум «лишнее» событие с тем
  же `seq`, которое отбросится. Пустые переходы (ADR-0124 «никого не нашли») событий не дают.
- Исходящие (`calls.go`, личные — §3): событие пишется только когда условный `UPDATE … WHERE status IN
  (…) RETURNING` реально сменил статус (вебхуки и ответ `CreateSIPParticipant` приходят дублями); `seq` =
  `max(seq)+1` под `SELECT … FOR UPDATE` строки звонка.
- Запись (ADR-0131): `recording/phone.go` при смене статуса `sip_call_recordings` вызывает
  `recording.JournalSink.RecordingEvent(call, status)` (интерфейс на стороне `recording`, реализует
  `sip.Service`; без импорта `sip` из `recording`), тот же приём `max+1`.
- **Нумерация вне машины.** У входящего `seq` событий машины — 1, 2, … из `InCall.Seq` (Valkey);
  события вне машины (запись, отказ до машины, звонок с потерянным состоянием) берут `max(seq)+1`, но не
  меньше **1000001**, — иначе событие записи заняло бы номер, который машина выдаст следующим, и
  `ON CONFLICT DO NOTHING` молча выбросил бы шаг машины. У исходящих машины нет — `max+1` с 1. Порядок
  чтения — `(at, seq)`.
- **Время ожидания** = `answered_at − started_at` (меню + гудки), для пропущенного — `ended_at −
  started_at`; **разговор** = `ended_at − answered_at`; «в очереди» = от первого `GROUP`/`RING` до
  `ANSWERED` — считается при чтении, не хранится.
- **Пропущенный**: входящий, на который никто не ответил (`answered_at IS NULL`) и звонящий дошёл хотя бы
  до одного `RING`, либо закончился в меню (`no_input`, `hangup_menu`) — для «Все звонки». Для «Мои» —
  пропущенный, где я `rang`. Ответил коллега — не пропущенный (строка «Ответил Борис»).
- **Старые звонки** (до T1) событий не имеют: деталь показывает разобранный `route` без времени
  (`sip.ParseLegacyRoute` на сервере → события с `at` = пусто) и подпись «Подробный маршрут — для звонков
  с выхода журнала».

**Хранение** (владелец 27.10). Настройка администратора «Хранение журнала»: 1, 3, 6 месяцев, 1, 2, 3
года; **по умолчанию 1 год**, «бессрочно» нет. Воркер раз в час (одна реплика, замок в Valkey) удаляет
законченные `sip_calls` (с событиями и участниками — каскадом) старше срока пространства, пачками по 1000
(≤ 50 пачек на пространство за проход — первый проход после выкатки не держит БД). **При выкатке T1
звонки старше года удаляются в течение часа** (срок по умолчанию применяется ко всем пространствам).
Звонок, у записи которого ещё лежит сырой файл (`sip_call_recordings.file <> ''`) или запись идёт, ждёт
уборщика записи. Записи разговоров на Диске живут по своим правилам (ADR-0131) и журналом не удаляются;
ссылка из журнала на удалённый файл — «Запись удалена» (деталь не отдаёт запись в корзине).
**Контакты** (T2) — тот же срок: удаляется контакт, ни один номер которого не звонил и которому не
звонили за срок **и** который никто не правил за срок (`updated_at`); крючок для T2 — в
`sip/retention.go`.

**Видимость** (нового бита нет — хватает существующих):
- **Все звонки пространства** — `VIEW_JOURNALS` (как сегодня; по умолчанию у ролей администраторов,
  ADR-0048). Звонки комнат, которых я не вижу, — как сегодня, пропускаются.
- **Свои звонки** — любой не гость: строки, где я в `sip_call_parties` (звонил, мне звонили, ответил,
  переводил/мне переводили). Номер абонента — полностью (я с ним говорил или он мне звонил).
- **Шаг живых звонков всех** (ADR-0128) — `MANAGE_INTEGRATIONS`, как сегодня; остальным — свои живые
  звонки из `SIP_CALL_UPDATE`.
- **Запись разговора** в детали — только если `perm.ComputeDiskItem` даёт мне `DISK_VIEW` на файл
  (ADR-0131 кладёт в `restricted`-папку владельца): иначе строки «Запись» нет вовсе.
- Боты (ADR-0109): чтение журнала — по тем же правилам (`VIEW_JOURNALS` / свои), только REST.
- Гости — ничего (404/403), раздела нет.

**API** (`/api/workspaces/{id}/sip/…`; `sip.proto`):
- `GET journal?scope=mine|all&filter=missed|in|out&user=<id>&q=<текст или цифры>&from&to&cursor&limit=50`
  → `ListSipJournalResponse {entries: SipJournalEntry[], next_cursor}`; ключ страницы — `(started_at,
  id)` по убыванию (курсор `<µs>.<id>`), `limit` 1..100. `scope=all` без `VIEW_JOURNALS` → 403. `q`:
  цифры — подстрока `peer_e164`/`number`, текст — контакты по имени/компании → их номера
  (`peer_e164 = ANY`; до T2 текст без цифр ничего не находит). `user` — только при `scope=all`.
- `SipJournalEntry {SipCall call; origin; peer_e164; contact (SipContactRef: id, name, company);
  member_user_id (номер совпал с номером сотрудника — §2); wait_ms; talk_ms; missed; parties
  (SipCallParty: user_id + флаги placed/rang/answered/transferred); has_events}` — сводка для строки
  списка, без событий. Участники — списком, а не «флаги для меня»: событие шлюза одно на всех
  получателей, клиент находит себя сам (участников звонка видят и так — в деталях).
- `GET journal/{cid}` → `{entry, events: SipCallEvent[], recording?: {file_id, disk_item_id,
  duration_ms}}`.
- `POST journal/seen` → `sip_seen_at = now()`; `WorkspaceSnapshot.sip_missed` (мои пропущенные после
  `sip_seen_at`) в READY только у тех, кому виден раздел; изменение — событием (ниже).
- `PUT sip/policy {retention_months, out_per_hour, out_per_user_hour}` — `MANAGE_INTEGRATIONS`, тариф
  телефонии, аккаунт сохранён; значения — в `SipSettings` (`GET …/sip`).
- **Старый** `GET /api/workspaces/{id}/calls` остаётся без изменений два релиза (окно настроек старых
  клиентов), затем удаляется (строка в docs/12).

**Живые обновления — без опроса.** Новое событие шлюза `SIP_JOURNAL_ENTRY` (`SipJournalChange {SipJournalEntry
entry}`, `DispatchEvent` 113) на три момента звонка: появился, ответили/перевели, закончился.
Получатели: сессии пространства с `VIEW_JOURNALS` (фильтр `eventScope`, как `SIP_CALLS_CHANGED`) и
пользовательские каналы участников звонка; одна сессия получает его один раз. Клиент вставляет/заменяет
строку в загруженной первой странице (если фильтры её пропускают), остальное не трогает. Для `sip_missed`
— `SIP_MISSED_CHANGED {workspace_id, count}` (114) в мой канал; `WorkspaceSnapshot.sip_missed` — в
`gateway.proto`. Детали звонка, открытой на экране, —
перечитываются по `SIP_JOURNAL_ENTRY` этого звонка (1 запрос на событие, только пока открыта).

### 2. Контакты (телефонная книга пространства)

**Модель** (миграция T2, `00030_sip_contacts.sql`):
- `sip_contacts (id uuid PK, workspace_id FK CASCADE, name text ≤ 128, company text ≤ 128, note text ≤
  1000, created_by/updated_by uuid SET NULL, created_at, updated_at, CHECK (name <> '' OR company <> ''),
  UNIQUE (workspace_id, id))`. ≤ 10 000 контактов на пространство.
- `sip_contact_phones (contact_id, workspace_id, number text CHECK (number ~ '^\+[1-9][0-9]{6,14}$'),
  label text CHECK (label IN ('mobile','work','home','other')), position smallint, PRIMARY KEY
  (contact_id, number), UNIQUE (workspace_id, number), FK (workspace_id, contact_id) → sip_contacts
  CASCADE)`. ≤ 10 номеров на контакт. **Номер принадлежит одному контакту** — сопоставление однозначно;
  повтор → `409 SIP_CONTACT_NUMBER_TAKEN` с id и именем владельца номера («уже у «ООО Ромашка»»).
- **Нормализация E.164** — та же `sip.NormalizeNumber` (пробелы/скобки/дефисы, `8…`/`7…` 11 цифр → `+7`,
  `00` → `+`), плюс для контактов и импорта: 10 цифр на `9` → `+7…`, если `caller_id` аккаунта начинается с
  `+7`. Иначе — `422 field=number` «укажите номер с кодом страны». Клиентское зеркало для маски и подсказок
  — `lib/phoneNumber.ts` (общие векторы `proto/testdata/phone_numbers.json`, как у прав).

**Кто может.** Читать — каждый, кому виден раздел (§5); создавать и править — тоже (общая записная книжка
команды; продавец добавляет клиента сразу после звонка); удалять — автор или `MANAGE_INTEGRATIONS`;
импорт и экспорт CSV — `MANAGE_INTEGRATIONS`. Боты — по тем же правилам (синхронизация из CRM). Нового бита
нет; если владелец захочет «только админы правят книгу» — бит телефонии по схеме ADR-0048 новым ADR.

**API**: `GET contacts?q&cursor` (по имени, затем компании; 200 на страницу; `q` — имя/компания/цифры),
`GET contacts/{id}` (+ последние 10 звонков с ним — те же правила видимости журнала), `POST contacts`,
`PATCH contacts/{id}` (номера — целым списком), `DELETE contacts/{id}`, `POST contacts/import`
(multipart CSV ≤ 1 МБ, ≤ 5000 строк, `dry_run=1` → предпросмотр), `GET contacts/export.csv`. События
шлюза — нет (книга меняется редко): клиент перечитывает при открытии списка и после своих правок.

**CSV** (дёшево, берём в T2): разделитель `,` или `;` (по первой строке), UTF-8 с BOM или без, при
невалидном UTF-8 — Windows-1251 (экспорт Excel на русской Windows); заголовки распознаются на ru/en
(`Имя|ФИО|Name`, `Компания|Организация|Company`, `Телефон*|Phone*|Мобильный|Mobile`, `Заметка|Note`),
несколько колонок телефона или несколько номеров через `,`/`;` в ячейке. Номер уже есть у контакта —
строка пропускается с причиной (молча не перезаписываем). Ответ: `{created, skipped: [{row, reason}]}`.
vCard — не делаем.

**Определитель номера (caller ID).** Порядок: контакт по `peer_e164` → сотрудник пространства по
нормализованному `User.phone` (ADR-0077: виден коллегам; сравнение в Go по снимку телефонов участников
пространства, кэш на 60 с) → номер. Где:
- **Модалка входящего, пуш, островок/полоса звонка**: `SipCall.caller_name`, `caller_company`,
  `contact_id`, `caller_user_id` (только вывод, заполняются при сборке `SipCall` для
  `SIP_INBOUND_RING`/`SIP_CALL_UPDATE` получателю). Пуш: «Входящий · ООО Ромашка — Анна Петрова».
- **Журнал**: имена **на момент чтения**, а не снимок — добавил контакт после звонка, и старые звонки
  показывают имя (как «Недавние» iPhone). Один запрос `number = ANY($1)` на страницу.

### 3. Исходящий звонок из раздела («личный»)

Путь через транк есть (ADR-0046), но только «линия в голосовую комнату». Для вкладки нужен личный звонок —
делаем его **зеркалом принятого входящего**:

1. `POST /api/workspaces/{id}/sip/calls {number | contact_id + number}` (новый метод на пути ADR-0128;
   `GET` там же — активные звонки). Проверки: не гость; **не бот** (v1: боту нужен свой LiveKit-клиент —
   звонит из комнаты, как раньше); тариф; `Workspace.sip_enabled`; **`PLACE_CALLS` на уровне пространства**
   (`perm.Resolver.Workspace`, без переопределений комнат — у личного звонка комнаты нет); номер
   нормализуется и проходит `allowed_prefixes`; лимиты (§ «Лимиты» ниже); я не занят (`user_call:<uid>` или
   ключ занятости входящих `inUserKey`) → `409 SIP_BUSY`.
2. Сервер: строка `sip_calls` (`out`, `origin = personal`, `dialing`, `started_by`, `lk_room =
   sipout_<ws>_<call id>`), ключ занятости (`inUserKey`, значит входящие группы меня пропустят, а
   DM-звонок получит «занято»), `CreateRoom` (`empty_timeout 30 с`, `max_participants 6`), событие
   `STARTED`, ответ `{call, join: JoinVoiceResponse}` (токен `sipout-caller:<user>`: микрофон + подписка,
   как у `accept` входящего).
3. Клиент: `voice.join(join, {call: true})` с паузой голосовой комнаты (ADR-0133, без изменений);
   островок/полоса звонка «Звонок · Анна Петрова · Набираем…», локальный гудок `call-outgoing` через
   `<audio>` до `ACTIVE` (правила эха docs/02 не меняются).
4. Вебхук `participant_joined` звонящего в `sipout_*` → `CreateSIPParticipant` (как `calls.go`,
   `wait_until_answered`, identity `sip:<call id>`, Caller ID — `sip_accounts.caller_id`). Звонящий не
   подключился за 15 с → `FAILED/not_connected`, комната закрывается. Набираем **после** входа звонящего,
   чтобы ответивший абонент не попал в пустую комнату.
5. Конец: `DELETE /api/workspaces/{id}/sip/calls/{cid}` (звонящий или `MANAGE_INTEGRATIONS`) → линия
   снимается, комната закрывается; абонент положил → `remote`; звонящий пропал 30 с → `lost` (как
   `answerGrace` входящих); 2 ч — `max_call_duration`. `SIP_CALL_UPDATE` — в канал звонящего (его другие
   устройства показывают «На звонке»).
6. `rtc.webhook` различает четвёртый вид комнат (`sipout_`), голосовые состояния пространства не
   трогает. Запись (ADR-0131 «Записывать исходящие») пишет комнату `sipout_*` — только две стороны (лучше,
   чем запись голосовой комнаты целиком).
7. **Тональный набор в разговоре** (меню банков, добавочные): клавиатура в островке/полосе звонка →
   `room.localParticipant.publishDtmf(code, digit)` (livekit-client 2.x); `livekit/sip` переводит его в RFC
   2833 к провайдеру. Работает и в принятом входящем. **Проверить в реализации** (`livekit/sip v1.14`):
   приём `SipDTMF` от участника комнаты и отправка провайдеру; не работает — кнопку не показываем, строка в
   docs/12.
8. **Внутренний номер** в наборе (2–6 цифр = `SipExtension` человека/бота) — это не внешний звонок:
   клиент предлагает «Позвонить Анне (вн. 101)» → обычный звонок ADR-0034 (бот — нельзя, как сегодня).
9. Звонок из голосовой комнаты (ADR-0046) остаётся как есть — для разговора с абонентом всей комнатой.
   Перевод **исходящего** личного звонка (ADR-0132 — только входящие) — не в этой версии.

**Лимиты** (владелец 27.10). Было 20 исходящих в час на всё пространство. Теперь — настройка
администратора (`PUT sip/policy`): в час на пространство (по умолчанию **120**) и в час на человека (по
умолчанию **30**), 1..1000 каждый; token bucket в Valkey (`rl:sip-call:<ws>`, `rl:sip-call-u:<ws>:<user>`),
размер корзины берётся из настройки при каждом звонке. `allowed_prefixes` и тариф — как раньше. С T1 оба
лимита действуют и для звонка из голосовой комнаты (ADR-0046); личный звонок (T2) — те же лимиты.

  `Grid3x3`, поповер с клавиатурой 3×4 для DTMF), «Перевести» (входящий), «Завершить»; модалка входящего —

### 7. UI — телефон (главный приоритет)

Телефон — та же сборка веб-клиента в оболочке (ADR-0067: Expo + WebView) и мобильный веб; разметка ≤ 768
px. Правила docs/08 «Мобильный веб»: стек экранов, одна `PhoneBack`, шапка `Bar` 48 px, контролы 36/цель 44,
меню и формы — карточки по центру, `Choice` вместо > 3 сегментов, `lib/haptics.ts`, `lib/rowSwipe.ts`,
`lib/longPress.ts`, safe areas, монтируется только верхний экран.

**Вход.** «Телефония» — раздел в карточке «Ещё» (ADR-0095), закрепляемый в панель вкладок (иконка-трубка,
бейдж пропущенных на вкладке и на строке «Ещё»). По умолчанию **не закреплён** (порядок закреплённых не
меняется у тех, кто уже настроил), но при первом появлении раздела у пользователя с `PLACE_CALLS` или
номером — разовая подсказка в «Ещё» «Закрепите «Телефонию»» (хранится в `prefs`).

### 8. Производительность (docs/14)

- Ничего не опрашивается: журнал — первая страница при открытии + `SIP_JOURNAL_ENTRY`; активные — как
  ADR-0128; контакты — при открытии; регистрация (ADR-0121, 15 с) — только на экране «Входящие» и только при
  видимом окне (как сегодня).
- Раздел не смонтирован — ни подписок, ни запросов; плитка рейла читает один примитив (`sip_missed`).
- Списки — `react-virtuoso`, строки `memo` с подпиской по id (`useShallow`-срез), события меняют одну
  строку. Таймеры — только у живых строк и в островке, листовой `useNow`, в скрытом окне стоят.
- Деталь: события звонка — ≤ ~60 строк, без виртуализации; перечитывается только на событие своего звонка.
- Сервер: события — 10–40 строк на звонок одной вставкой; список — индекс `(workspace_id, started_at
  DESC, id)` и `sip_call_parties`; имена контактов — один `ANY` на страницу. Хранение — часовой воркер,
  пачки по 1000.
- Перед мержем T3/T4: `CALABA_REACT_PROFILING=1` + `tools/perf-call.ts` — новое событие журнала
  перерисовывает одну строку; цифры в docs/14 («Телефония»).

## Почему не иначе

- **Событийный лог в JSONB одной колонкой `sip_calls`** — проще миграция, но нет ни ключа
  идемпотентности на шаг, ни запросов «мои звонки»; растёт перезаписью строки на каждом шаге.
- **Снимок имени контакта в журнале** — журнал не узнал бы контакт, добавленный после звонка (главный
  сценарий «записал клиента после первого звонка»). Имена шагов маршрута, наоборот, снимок — меню и группы
  удаляются.
- **Новый бит «Телефония» (ADR-0048 ≥ 32)** — сейчас существующих хватает (`VIEW_JOURNALS`,
  `MANAGE_INTEGRATIONS`, `PLACE_CALLS`, участие); бит — отдельным ADR, если владелец попросит разделить.
- **Исходящий из раздела как звонок из «личной» голосовой комнаты** — та же цена, но в списке комнат
  появилась бы сущность, которой нет; путь «как принятый входящий» уже отлажен (пауза, островок, перевод,
  запись).
- **Своя вкладочная панель раздела на телефоне** (как в «Телефоне» iPhone) — вторая нижняя панель над
  панелью приложения; три сегмента сверху + FAB «Набор» внизу дают то же одной рукой.
- **Тап по строке открывает деталь** (безопаснее платного звонка) — владелец и координатор просят
  паттерн iPhone; защита — срабатывание только по отпусканию без прокрутки, видимый `ⓘ` для детали.

## Значения по умолчанию, выбранные без владельца

- Раздел последним на рейле; на телефоне — в «Ещё», не закреплён, с разовой подсказкой.
- Тап по строке «Недавние» на телефоне — звонок; на десктопе — деталь (звонок — кнопкой в строке).
- Свои звонки видит каждый участник с доступом к разделу; все — `VIEW_JOURNALS`; новых битов нет.
- Контакты правит любой с доступом к разделу, удаляет автор или `MANAGE_INTEGRATIONS`; CSV —
  `MANAGE_INTEGRATIONS`; номер — у одного контакта.
- Имя звонящего — контакт, затем телефон сотрудника из профиля, затем номер.
- Личный исходящий: Caller ID — номер пространства; боты не звонят лично; перевода исходящего нет.
- Без группировки повторных звонков с одного номера в одну строку (iPhone «(3)») — v1 показывает каждый
  звонок; группировка — позже, если попросят.
- Старые звонки без маршрута с временем — показываем разобранный `route` без времени.
- Бейдж пропущенных считает звонки после `sip_seen_at`; при выкатке у всех `sip_seen_at = now()`.

## Решения владельца (27.10)

1. **Срок хранения журнала и контактов с номерами внешних людей** — настройка администратора: 1, 3, 6
   месяцев, 1, 2, 3 года; **по умолчанию 1 год**, «бессрочно» нет. Старое удаляет часовой воркер; при
