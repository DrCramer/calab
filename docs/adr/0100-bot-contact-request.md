# ADR-0100: Бот запрашивает контакт пользователя — кнопка «Поделиться контактом» (2026-10-14)

## Контекст
Владелец, 14.10: «бот должен иметь возможность запросить контакты пользователя, чтобы юзер мог через кнопку одобрить передачу контактов — телефон/почта и статус: подтверждено или нет (как в Telegram)».

Есть: inline-кнопки ботов ([ADR-0047](0047-bot-inline-buttons.md)), DM с ботом, профиль с почтой и телефоном ([ADR-0077](0077-profile-contacts-username.md)), подтверждение почты ([ADR-0065](0065-optional-email-verification.md)). Боту контакты людей сейчас не выдаются.

## Решение
1. **Новый вид кнопки** `REQUEST_CONTACT` в `InlineButton` (рядом с callback/url): поля `fields` — `PHONE`, `EMAIL` (одно или оба), необязательный `reason` (≤ 120 символов, показывается человеку). Только в DM бота с человеком (как в Telegram — в личке); в комнатах сервер такую кнопку отклоняет при отправке (`400 BOT_CONTACT_REQUEST_DM_ONLY`).
2. **Клиент**: кнопка «Поделиться контактом» (иконка телефона). Тап → карточка подтверждения: «Бот @name получит: телефон +7 … (подтверждён / не подтверждён), почта … (подтверждена / не подтверждена)» + причина бота; «Поделиться» / «Отмена». Пустое поле профиля — строка «не указан» (не передаётся). Без подтверждения ничего не уходит.
3. **Сервер — источник правды**: `POST /api/messages/{id}/buttons/{buttonId}/contact` (без тела). Сервер проверяет: сообщение — от бота в DM, где вызывающий — второй участник; кнопка `REQUEST_CONTACT`; лимит (≤ 1 отдачи на кнопку на человека, ≤ 10 в час на человека). Контакт собирается **из профиля на сервере**, клиент значения не присылает. Поля: `user_id`, `display_name`, `phone`, `phone_verified`, `email`, `email_verified`, `shared_at`, только запрошенные кнопкой и непустые.
4. **Доставка боту**: событие шлюза `CONTACT_SHARED` (только этому боту) и тот же payload в бот-вебхук; в DM появляется системная строка «Вы поделились контактом с @bot: телефон, почта» (видят оба) — это и квитанция для человека. Повторный тап после отдачи — кнопка в состоянии «Отправлено».
5. **Подтверждённость**: `email_verified` — из подтверждения почты (ADR-0065); `phone_verified` — `false`, пока в продукте нет подтверждения телефона (поле есть в контракте заранее).
6. **SDK**: `bot.sendMessage(..., { buttons: [[{ kind: 'requestContact', fields: ['phone','email'], text, reason }]] })`, обработчик `bot.on('contactShared', …)`; документация на сайте — глава «Команды и кнопки».
7. **Журнал**: запись в журнал пространства/аудит (кто, какому боту, какие поля, когда) — `VIEW_JOURNALS` видит факт отдачи без значений.

## Последствия
- Протокол (proto `InlineButton`, `ContactShared`, событие, маршрут), персональные данные → Opus + второе ревью.
- docs/04, 05, 08 («Кнопки ботов»), 16, публичная документация ботов.

## Альтернативы
- **Бот читает контакты через API по праву** — без согласия человека; отклонено.
- **Клиент присылает контакт** — можно подделать «подтверждено»; отклонено, собирает сервер.
