# ADR-0107: Ссылки временной комнаты переживают архив и постоянство; управление ссылками (2026-10-19)

**Статус: принято.** Меняет [ADR-0044](0044-temp-rooms.md) «Дополнение 14.10» (что происходит со
ссылками при «Вернуть» и «Сделать постоянной»), дополняет [ADR-0016](0016-guest-access.md) (ссылка —
capability), [ADR-0040](0040-guest-admission.md) (PATCH ссылки), [ADR-0043](0043-invite-permissions.md)
(кто управляет какими ссылками), учитывает [ADR-0078](0078-private-temp-rooms-hidden-from-admins.md).

## Контекст
Владелец, 19.10: «когда временную комнату восстанавливаешь, гостям больше нельзя туда заходить; ещё я бы
сделал возможность делать комнаты постоянными (в т.ч. ссылки которые были надо тоже делать постоянными),
добавить возможность управлять ссылками». По ADR-0044 архив отзывает все ссылки комнаты, а «Вернуть»
выдаёт одну свежую ссылку «только для участников» — разосланная гостям ссылка умирает навсегда. «Сделать
постоянной» оставляет ссылкам их срок (= конец временной комнаты): постоянная комната со ссылками, которые
вот-вот истекут. Изменить у ссылки можно было только режим «пускать сразу / ждать одобрения».

## Решение

### 1. Архив помечает отозванные им ссылки
`room_invites.archive_revoked boolean NOT NULL DEFAULT false` (миграция `00103`). Архивация (DELETE и свипер)
отзывает все ссылки, как раньше, и ставит флаг тем, что были пригодны в этот момент: не ссылка встречи
(`event_id`), не исчерпана (`max_uses`), и срок не истёк или привязан к комнате (≥ конца комнаты — свипер
архивирует уже истёкшую комнату). Отозванная вручную ссылка флага не имеет и **не возвращается никогда**.
Бэкфилл: ссылки комнат, лежащих в архиве сейчас, с `revoked_at = archived_at` (одна транзакция архивации) и
теми же условиями.

### 2. «Вернуть» возвращает ссылки
`POST /api/rooms/{id}/restore` в той же транзакции возвращает помеченные ссылки:
- срок ≤ прежнего конца комнаты (привязана к комнате) → новый конец комнаты; свой срок впереди — остаётся;
  истёк — новый конец комнаты; бессрочная — бессрочная;
- **гостевые** (не `members_only`) — только если у вернувшего `INVITE_GUESTS` на уровне пространства, он не
  бот (ADR-0031) и почта подтверждена, где это требуется (ADR-0023/0065), — то же, что для создания гостевой
  ссылки временной комнаты; ссылки с правами шире, чем у вернувшего в комнате (без `ADMINISTRATOR`), не
  возвращаются (нет эскалации через ссылку);
- невозвращённые остаются отозванными **навсегда** (флаг снимается: решение принимается один раз, при
  возврате, а не «всплывает» при следующем возврате другим человеком);
- свежая ссылка «только для участников» создаётся, только если не вернулось ни одной.
Ответ и события не меняются; списки ссылок просто снова их показывают.

### 3. «Сделать постоянной» делает ссылки бессрочными
`POST /api/rooms/{id}/make-permanent` (и `make_permanent` в `PATCH /api/rooms/{id}`): ссылки, срок которых
равен концу комнаты, становятся бессрочными (`expires_at = NULL`); у архивной комнаты сначала ссылки
возвращаются по п. 2 (с «новым концом» = никогда). Гостевые — с тем же условием `INVITE_GUESTS` (без него
живая гостевая ссылка сохраняет свой срок, архивная — не возвращается). В приостановленном пространстве
ссылки не трогаются. Клиент: «Сделать постоянной» есть и в меню живой временной комнаты (только при
`MANAGE_ROOM` на уровне пространства, как кнопка в архиве), подтверждение говорит, что ссылки станут
бессрочными.

### 4. Управление ссылками
`PATCH /api/rooms/{id}/invites/{invite_id}` (`UpdateRoomInviteRequest`) кроме одобрения принимает
`expires_in_seconds` (от «сейчас», 0 = бессрочно, ≤ 365 дней), `max_uses` (0 = без ограничений, ≤ 10000 и
больше уже сделанных переходов, иначе `422`), `allow_speak/messages/files/stream` (в пределах своих прав,
иначе `403`). Меняются только заданные поля, хотя бы одно. Права — как на создание этого вида ссылки
(ADR-0043): гостевая — `INVITE_GUESTS` (`403` без него), `members_only` — ещё `INVITE_MEMBERS` или создатель
временной комнаты (ADR-0044); одобрение — по-прежнему `INVITE_GUESTS` и только у гостевых. Ссылки встреч не
правятся (они следуют за встречей, `422`). `members_only`/`allow_guests` не меняются — новая ссылка. Правка
срока/прав в приостановленном пространстве — `403 WORKSPACE_SUSPENDED` (как создание); требует подтверждённой
почты, как создание. Срок ссылки живой временной комнаты может быть и дольше комнаты: архив её всё равно
отзовёт (и пометит).

Клиент: «Настройки комнаты → Ссылки» — у каждой активной ссылки «Изменить» (карандаш) раскрывает под
строкой редактор: срок («Не менять · до …» / 1 час / 1 день / 7 дней / бессрочно), лимит переходов, права;
сохраняется только изменённое. Вкладка видна и с одним `INVITE_MEMBERS` или создателю временной комнаты
(тогда создаются только ссылки «только для участников»; заголовок «Ссылки на комнату»). Меню временной
комнаты: «Ссылки…» (кто управляет её ссылками) открывает эту вкладку.

## Последствия
- Разосланные гостям ссылки снова работают после «Вернуть» — если вернул тот, кто вправе звать гостей.
- Возврат комнаты человеком без `INVITE_GUESTS` окончательно хоронит гостевые ссылки; их нужно выпустить
  заново. Это осознанно: возврат не должен давать больше, чем создание.
- Ссылки, отозванные архивом до миграции у уже возвращённых комнат, не восстанавливаются (флага нет).
- Маршруты не менялись: `PATCH …/invites/{id}` — `botDeny`, `RestrictedInvite`, `scopeRoom`.
