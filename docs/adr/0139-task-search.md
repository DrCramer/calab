# ADR-0139: Поиск задач — один поиск и одни фильтры в ⌘K, на странице, на доске (2026-10-27)

**Статус: принято.** Задача доски #95 (владелец 27.10). Расширяет [ADR-0062](0062-unified-search.md)
(раздел «Задачи»), [ADR-0105](0105-search-panel-beside-boards.md) и ADR-0042 §3 (универсальный
фильтр). Миграция **00128**.

## Контекст
Поиск задач был в трёх местах и везде разный: ⌘K — четыре строки среди десяти разделов (фильтры
только автор/доска/период), «Мои задачи → Все задачи» — строка по названию и «Незавершённые /
Завершённые / Все», доска — «Фильтр» (F) без текста. Задачи в архиве не находились нигде.
Референс — Яндекс Трекер: строка поиска (ключ открывает карточку), страница с панелью параметров
и сохранёнными фильтрами, то же внутри очереди.

## Решение
1. **Один серверный поиск** — существующий `GET /api/workspaces/{id}/tasks/search`, расширенный
   (старые вызовы и боты отвечают как раньше):
   - `q` 0..200 (пусто — только фильтры); текст — ключ, название, описание (как раньше) **и
     комментарии** (комнаты задач, найденные тем же GIN-индексом `messages_search_idx`, только
     среди видимых задач; на таймауте поиск по комментариям пропускается, а не роняет ответ);
   - `state` `open|done|all` (как раньше) + новый `archived`: пусто — только живые (как раньше),
     `1` — живые и архив, `only` — только архив; клиентский переключатель «Все / Незавершённые /
     Завершённые / В архиве» = `all+1 / open / done / only`;
   - `board_id` — область одной доски (видимой, иначе 404); `filter` — `TaskFilter` JSON, тот же
     `Translate`, что у `GET /boards/{id}/tasks`; новое поле **`TASK_FIELD_BOARD`** (id досок);
   - `sort` — `relevance` (по умолчанию с текстом), `updated` (без текста), `created`, `key`,
     `title`, `board`, `status`, `assignee`, `priority`, `due`; `-` — по убыванию;
   - курсор — непрозрачный сдвиг (≤ 2000 строк; выдача отсортирована по выражению, keyset не
     подходит релевантности); `limit` 1..50.
   - Ответ: `tasks`, `next_cursor`, **`key_task`** — задача, чей ключ набран (`DOC-426`, любые
     написания `ParseLooseKey` кроме голого номера), видимая вызывающему, **в обход фильтров,
     области и архива** («по ключу задача находится всегда»), и `snippets` — фрагмент описания или
     последнего совпавшего комментария с маркерами подсветки, когда совпало не название.
   - Права — только существующие: `VisibleBoards` (полный доступ + доступ по карточке, ADR-0059:
     у последнего — только живые задачи, как во всех списках); архивная задача доски с полным
     доступом находится и помечена `archived_at`.
2. **Сохранённые фильтры** — на сервере, по пользователю и пространству (дёшево, и видны на
   телефоне): таблица `task_searches (id, workspace_id, user_id, name ≤ 60, query jsonb, position)`,
   ≤ 50 на человека в пространстве; `GET/POST /api/workspaces/{id}/task-searches`,
   `PATCH/DELETE /api/workspaces/{id}/task-searches/{sid}` — только свои. `query` — `TaskSearchQuery {q, state,
   filter, sort}`; сервер хранит, не исполняет — права проверяет поиск при каждом запуске.
   Удаление участника из пространства — `ON DELETE CASCADE` по членству не нужен: строка без
   членства никому не отдаётся (проверка членства в каждом маршруте).
3. **Клиент — один компонент `TaskSearch`** (строка + «Все / Незавершённые / Завершённые / В
   архиве» + чипы условий из того же `FilterPopover`/`ConditionChips`, что у доски + список с
   сортировкой по колонке и подгрузкой) в четырёх местах:
   - **⌘K**: вкладки «Задачи · Всё» над результатами; «Задачи» первая и открыта по умолчанию в
     режиме досок, иначе — «Всё» (быстрое переключение комнат не ломается); набранный ключ —
     строка «Открыть DOC-426» первой, ↩ открывает карточку; ⌘↩ — страница результатов;
   - **страница** «Поиск задач» в колонке досок (бывшая вкладка «Мои задачи → Все задачи» — та же
     страница) и **сохранённые фильтры** строками под «Мои задачи»;
   - **доска**: строка поиска в шапке доски; пока в ней есть текст, вместо канбана — тот же список,
     ограниченный доской, с фильтром доски (F) как условиями; без текста — канбан с тем же
     фильтром локально, как раньше. Поле «Текст» из списка полей фильтра убрано (оно и есть
     строка поиска); старые виды с ним продолжают работать;
   - **телефон**: тот же компонент, строки — карточки (без таблицы).
   Последние условия (текст, переключатель, условия, сортировка) запоминаются по пространству в
   localStorage; условия доски — как раньше, в настройках доски.

## Не входит
Язык запросов (`доска:DOC статус:открыт`), выгрузка XLSX, группировка, подзадачи — в
docs/09-ui-backlog. Поиск по архивным доскам (сама доска в архиве) — как раньше, нет.

## Последствия
- `TASK_FIELD_BOARD` локально на доске всегда истинен для своей доски — клиентский матчер его знает.
- Поиск без текста по всему пространству и архиву читает все видимые задачи, поэтому (ревью
  безопасности #95) в процессе одновременно идут ≤ 4 поиска задач (ждут слот ≤ 1 с), а запросы
  ключа, задач и фрагментов — с `statement_timeout` 3 с; сверх — 503 (фрагменты просто не
  приходят), а не занятый пул БД.
- Сдвиг-курсор может пропустить/повторить строку, если между страницами задача поменялась; для
  поиска это приемлемо (Трекер ведёт себя так же).
