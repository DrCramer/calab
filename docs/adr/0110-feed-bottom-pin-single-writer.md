# ADR-0110: Низ ленты держит один механизм — bottom pin; без column-reverse (2026-10-19)

**Статус: принято.** CBF-13 «Сообщения в чате не сразу видно».

## Контекст
Владелец: «если я в конце чата и приходит сообщение — нужно придерживаться конца чата и показывать его;
эту проблему уже не первый раз правим». История: #149 (ResizeObserver на последней строке + `atBottom`
Virtuoso — порог 48 px срывался на росте картинки), 2.4.1 `eebcc44a` (стик решает только прокрутка
читателя, RO на скроллере и списке), `6ccfd768` (кламп при прокрутке вверх не прилепляет), `f47492b2`
(своя отправка прилепляет). Каждый фикс чинил один путь, но чужое новое сообщение оставалось за
`followOutput: 'smooth'` Virtuoso, а первый ресайз новой строки пин пропускал («fresh»). Virtuoso целится в
**оценочную** высоту строки; строка выше оценки (несколько строк, превью ссылки, карточка) оставалась под
композером, а следующего ресайза, который бы это поправил, не было. Воспроизведено e2e: однострочное
чужое сообщение — 92 px под композером при 960×600 и 390×844.

## Решение
1. **Один писатель «вниз»** — `BottomPin` (`features/chat/lastRowPin.ts`). `followOutput` у ленты нет.
   Любой отчёт ResizeObserver при «прилипшем» состоянии (новая строка, её рост, превью, картинка, реакция,
   правка, композер, окно, возврат скрытого окна) → `scrollTop = scrollHeight` до отрисовки кадра.
   Список Virtuoso наблюдается по `border-box` — в него входит паддинг неотрисованных строк.
2. «Прилип» решает только прокрутка читателя (правила 2.4.1/`6ccfd768` без изменений), своя отправка —
   `stick()`, раскрытие «Показать всё» — `release()`. Прокрутил вверх — лента не двигается, «К новым» со
   счётчиком.
3. Новое сообщение у низа появляется мгновенно, без плавной прокрутки: плавная цель устаревает при
   росте строки, а в скрытом окне анимация не идёт.

## Почему не `flex-direction: column-reverse`
- Лента виртуализирована (Virtuoso + наш патч, 20 тыс. сообщений, docs/14) — Virtuoso не умеет обратную
  колонку; без виртуализации — тысячи строк в DOM, против бюджета CPU/памяти.
- Обратная колонка переносит ту же задачу на догрузку истории сверху (якорь вверху теряется) и ломает
  firstItemIndex/восстановление позиции; отрицательный `scrollTop` у WebKit/iOS WebView (телефон) исторически
  с багами инерции.
- Перевёрнутый DOM-порядок портит порядок Tab/скринридера, поиск по странице и выделение текста; обёртка
  «одна внутренняя колонка» это лечит, но не виртуализацию.
- CSS `overflow-anchor` в Chromium не якорит к низу (он держит видимый узел), а Virtuoso его и так отключает.

## Затраты
Нет таймеров и кадровых циклов: RO вызывается браузером только при изменении размера; в простое — 0 работы.
