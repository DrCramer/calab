# ADR-0131: Запись телефонных звонков на Диск пространства (2026-10-23)

**Статус: принято** (задача CBF-81, ТЗ владельца 23.10). Опирается на [ADR-0025](0025-meeting-transcription.md)
(запись встреч: LiveKit Egress, volume/бакет, reconcile), [ADR-0094](0094-disk.md) (Диск, `restricted`,
квота), [ADR-0117](0117-sip-inbound-ivr.md) (входящие, IVR-воркер), [ADR-0129](0129-sip-ivr-barge-in-extension-dialing.md)
(набор добавочного), [ADR-0048](0048-roles-v2.md) (`MANAGE_INTEGRATIONS`).

## Контекст

Владелец: на вкладке «Настройки» телефонии две галочки «Записывать входящие звонки» / «Записывать
исходящие звонки» (по умолчанию выкл.); записи — на Диск пространства:
`/phone_recordings/2026_06_15/202606151200_74955555555_IN.ogg`; нет папки — создать от владельца пространства
с доступом «только владелец», доступ он выдаёт сам. В голосовом меню — необязательный файл «предупреждение о
записи» (правила как у приветствия), играет звонящему прямо перед переводом на сотрудника/бота/группу (по
кнопке или набором номера), не перед другим меню; нет файла — ничего не играет. Запись включают только
галочки.

## Решение

1. **Что пишем.** Аудио LiveKit-комнаты звонка целиком: room composite egress, `audio_only`, файл **Ogg/Opus**
   (`EncodedFileType OGG`; `rtc.FileOutput.FileType = FileOGG`). Входящий — комната `sipin_*` (звонящий и
   ответивший, и всё, что произойдёт в этой комнате дальше — перевод внутри звонка CBF-84 попадает в ту же
   запись). Исходящий — голосовая комната, из которой звонят: **в запись попадают все, кто говорит в комнате
   во время звонка** (так устроен исходящий звонок ADR-0046; подсказка у галочки это говорит). Track composite
   отклонён — он пишет один трек, нам нужен микс.
2. **Когда.** Старт — когда звонок дошёл до человека/бота: входящий — `Answer` (не во время меню и гудков),
   исходящий — `MarkSipCallActive` (ответ вызываемого; дубль из вебхука ничего не добавляет: `UNIQUE(call_id)`).
   Стоп — при завершении звонка (`StopEgress`; у входящего комната и так закрывается). Хуки в `internal/sip` —
   два вызова `CallRecorder.CallConnected/CallEnded`, оба возвращаются сразу (egress стартует в горутине до
   минуты) — **звонок никогда не ждёт записи и не страдает от её сбоя**: лог + метрика
   `calaba_sip_recordings_total{result}` (`started`, `stored`, `skipped_limit`, `failed_<причина>`).
3. **Где живёт логика.** `internal/recording/phone.go` (тот же сервис, что запись встреч): общий egress-клиент,
   хранилище сырого файла (volume `RECORDINGS_PATH` или бакет при `STORAGE_DRIVER=s3` — ключ
   `phone/<workspace>/<id>.ogg`), webhook `egress_ended`, воркер. Таблица `sip_call_recordings`
   (`starting → recording → stored | failed`, `egress_id`, `file`, `file_id`, `disk_item_id`). Reconcile встреч
   не трогает egress телефонных записей (по `egress_id` и по комнатам ещё стартующих); `maintainPhone` раз в
   15 с подбирает потерянные вебхуки (`ListEgress` по id), повторяет стоп, останавливает egress старше 2 ч 5 мин,
   валит «застрявший старт» через 2 мин; janitor убирает сырые файлы неудачных записей через 7 дней.
4. **Диск.** По концу egress файл копируется в хранилище файлов через `files.StoreSystemFile` (квота
   пространства и сервера, как у любого файла; места нет — `failed/quota`, звонок не затронут) и
   `disk.PlaceFile` кладёт его в `/phone_recordings/YYYY_MM_DD/` — недостающие папки создаются от
   **владельца пространства**, корневая с `restricted` («Только выбранные»: видит владелец, админы — нет,
   ADR-0094 доп. 14.10), дневные наследуют. Существующая папка `phone_recordings` (без учёта регистра, не в
   корзине) используется как есть — её доступ решает владелец, — **только если она его**: такую же папку,
   заранее созданную участником, сервер не трогает (`failed/path_blocked`) — владелец папки видит всё внутри. Файл с таким же именем в корне блокирует путь —
   `failed/path_blocked`. Имя файла — `YYYYMMDDHHMM_<цифры номера>_<IN|OUT>.ogg` по времени начала записи,
   совпадение в ту же минуту — «(2)» перед расширением; номер без цифр — `unknown`. Журнал Диска — записи без
   автора (сервер). Однократность копирования — замок Valkey на запись (вебхук и reconcile могут прийти оба).
5. **Часовой пояс.** У пространства своего пояса нет — имена в **`SIP_RECORDING_TZ`** (IANA, по умолчанию
   `UTC`); на установке в России devops ставит `Europe/Moscow`. Если у пространства появится пояс — брать его.
6. **Права.** Галочки — `PUT /api/workspaces/{id}/sip/recording` (`MANAGE_INTEGRATIONS`, тариф телефонии, боты —
   как люди ADR-0109; до сохранения провайдера — 409). `updated_at` настроек не меняется (форма провайдера
   не пересоздаётся). Видимость записей — только ACL Диска. `SipSettings.recording_available` — на сервере есть
   egress.
7. **Предупреждение о записи.** `sip_ivr_menus.notice_file_id/notice_duration_ms`; загрузка — как у приветствия
   (`notice_source_file_id` в create/PATCH, свой файл ≤ 10 МБ, ≤ 3 мин, ffmpeg → Ogg/Opus, квота). В машине
   состояний: кнопка или набранный номер, ведущие к звонку (Route → `ActRing`), при наличии файла сначала
   ставят `InCall.Notice` (фаза остаётся «меню», кнопки не принимаются) и играют файл; по «played» воркера
   (или по дедлайну длительность + 3 с) звонок идёт туда, куда вела кнопка. «played» раньше 300 мс после
   начала — от прерванного приветствия, игнорируется. Перед другим меню, «положить трубку» и «если ничего не
   нажали» не играет. Воркер берёт файл тем же `GET /internal/ivr-agent/files/{id}`.
8. **Лимиты.** `SIP_RECORDING_MAX_CONCURRENT` (по умолчанию 10) одновременных записей на сервер — сверх них
   звонок не пишется (лог + `skipped_limit`); egress общий со встречами.

## Юридическое

Предупредить звонящего о записи — **обязанность администратора пространства**: для этого файл
«Предупреждение о записи» в меню (и текст в подписи карточки). Сервер не проверяет, что предупреждение есть,
и запись от него не зависит. Исходящие звонки предупреждения не имеют — сотрудник говорит сам.

## Последствия / проверить на проде

- Нужен работающий egress (как для записи встреч, docs/06): API ↔ `LIVEKIT_INTERNAL_URL`, egress ↔ хранилище
  (volume или бакет). Без egress галочки сохраняются, запись не идёт (лог `start egress`).
- Проверить на стенде: audio-only room composite в комнате `sipin_*` (без Chrome на egress 1.14), что
  egress-участник не упирается в `max_participants` правила dispatch (поднят с 4 до 6: линия, воркер,
  ответивший, перевод CBF-84, egress, переподключение; LiveKit не должен считать участника-egress, но на стенде
  не проверено; старые правила получают 6 при следующем сохранении настроек телефонии), длительность/размер Ogg
  (~16–32 кбит/с ≈ 7–15 МБ/ч).
- Отклонено: запись в API (pion) — ADR-0013; запись только звонящего (participant/track egress) — не слышно
  ответившего; автоудаление записей — не просили, место считает квота.
