# ADR-0028: Указка и карандаш поверх показа экрана (2026-09-27)

## Контекст
docs/09 #42 (владелец): зритель стрима указывает («Указка» — точка с именем) и рисует («Карандаш», «Очистить»), все зрители видят это поверх плитки, ведущий — на своём реальном экране, как в Zoom. Нужны транспорт, лимиты, права и граница «только пока стрим идёт».

## Решение
1. **Транспорт** — LiveKit data channel, reliable, topic `annot`, broadcast в комнату. Не gateway: сигнал эфемерный и живёт только внутри звонка (ADR-0007), путь через SFU короче. Сервер сообщения не видит и не хранит.
2. **Сообщение** — `calaba.v1.AnnotMessage` (`proto/calaba/v1/annot.proto`): `stream_sid`, `kind` POINTER | STROKE | CLEAR | POLICY, `color` 0xRRGGBB, `points` — packed float `x0,y0,x1,y1…`, нормированные 0..1 к **кадру видео** (не к элементу: letterbox учитывается при рисовании), `seq` (растёт у отправителя), `stroke_id`/`stroke_end` (батчи одного штриха), `allow` (POLICY). Имени в сообщении нет — берётся по identity отправителя, которую проставляет SFU.
3. **Лимиты.** Отправитель: ≤ 20 сообщений/с (указка — последняя позиция раз в 50 мс, штрих — батч точек раз в 50 мс, ≤ 60 точек, прореживание < 0.002), сообщение ≤ 1 КБ (кодек не кодирует больше). Получатель: token bucket 30/с на identity (burst 30); сверх лимита и невалидное (NaN, вне 0..1, нечётное число координат, > 60 точек, > 1 КБ, `seq` не растёт) выбрасывается молча. Валидация одна (`lib/annot`) — у зрителей и в оверлее ведущего.
4. **Жизненный цикл.** Принимается только `stream_sid`, опубликованный сейчас как ScreenShare в комнате; стрим снят → сцена очищена, оверлей закрыт. Указка гаснет через 1 с после последнего сообщения; штрих живёт 5 с после последней точки (последнюю секунду тает). CLEAR ведущего стирает всё, CLEAR зрителя — только его штрихи.
5. **Запрет ведущим.** Переключатель «Рисование зрителей» в панели своего стрима (по умолчанию вкл.). Состояние — POLICY: broadcast при смене и адресно зрителю, приславшему `calaba.watch` «смотрю»; принимается только от владельца трека `stream_sid`. Выключено → у зрителей скрыты инструменты и очищена сцена, входящие игнорируют все, включая оверлей. Metadata/attributes участника не используем: `canUpdateOwnMetadata` в гранте нет, расширять грант ради флага не стоит.
6. **Права** — рисует тот, у кого в комнате есть SPEAK (сервер, `computePermissions`); гость — только если override комнаты/ссылки даёт ему SPEAK (ADR-0016). Дыра: `canPublishData` выдаётся всем с CONNECT (`internal/rtc/grant.go`, нужен слушателям для `calaba.watch`), а сервер data не видит. Закрываем на приёме: каждый получатель проверяет **грант отправителя** из ParticipantInfo (выдаёт наш сервер через LiveKit, identity пакета ставит SFU — подделать нельзя): `canPublish` и `MICROPHONE ∈ canPublishSources` (пустой список = все источники). Нет SPEAK → сообщение выброшено, инструменты скрыты. Изменений сервера и гранта нет: отбирать `canPublishData` у слушателей сломало бы счётчик зрителей.
7. **Ведущий (desktop)** — прозрачное click-through окно main: `transparent, frame:false, focusable:false, hasShadow:false`, `alwaysOnTop 'screen-saver'`, `visibleOnAllWorkspaces {visibleOnFullScreen}`, `setIgnoreMouseEvents(true)`, bounds = `display.bounds` расшаренного экрана. Открывается лениво при первой аннотации, закрывается с концом стрима/запретом. Своя страница `overlay.html` + узкий preload (только приём событий); сцена и рисование — тот же `lib/annot`, что у зрителя. Renderer ведущего шлёт в main уже провалидированные события.
8. **Оверлей не попадает в шаринг** — `setContentProtection(true)`. Проверено 27.09 на macOS 27 / Electron 44: защищённое окно отсутствует и в `desktopCapturer`-thumbnail, и в кадре `getDisplayMedia` (ScreenCaptureKit), незащищённое контрольное окно в кадре есть. Windows: `WDA_EXCLUDEFROMCAPTURE` (Win10 2004+) — на железе не проверено. Linux: защиты нет → оверлей не открываем, ведущий видит аннотации в превью своего стрима.
9. **Шаринг окна** — только превью. Electron не отдаёт границы чужого окна (`desktopCapturer` даёт лишь `window:<id>`); нужен нативный CGWindowList/GetWindowRect плюс слежение за перемещением и перекрытием. Не делаем: для окна аннотации видят зрители и ведущий в превью своего стрима (docs/12 — возможное развитие).
10. **Мобильный веб** — зритель указывает и рисует пальцем (pointer events, `touch-action: none` при активном инструменте); оверлея нет.

## Последствия
- Новый proto без изменений сервера; UI — плитка/stage/полный экран/pop-out, эталон `stream-annotate`.
- Злоумышленник с SPEAK может засорять сцену в пределах 30/с — как и голосом; ведущий выключает рисование.

## Поправка (2026-10-29, #102: у ведущего на Windows и в вебе рисунки не видны)
- **Причина на Windows.** Оверлей ищет дисплей по `display_id` источника `desktopCapturer`. На macOS это CGDirectDisplayID — тот же id, что у `screen.getAllDisplays()`. На Windows Electron сопоставляет источник с дисплеем через имена выходов DXGI: где DXGI-дубликация недоступна (ноутбуки с двумя GPU, RDP, часть драйверов), id пустой; где захватчик перечисляет мониторы иначе, чем screen API, id не совпадает ни с одним дисплеем. Тогда `presenting()` получал `null` (пустой id) или `openOverlay` — «нет дисплея», и оверлей молча не открывался; у других машин всё работало — отсюда «не у всех».
- **Решение.** `main/capture.ts` дополняет id (`shared/annot` `resolveScreenDisplays`): совпавшие остаются, один несопоставленный источник получает оставшийся дисплей, иначе — единственный дисплей с тем же соотношением сторон миниатюры; неоднозначное (два одинаковых монитора без id) остаётся пустым — оверлей не откроется на чужом мониторе. `displayBoundsFor` при одном дисплее берёт его при любом id. Renderer передаёт цель для любого `screen:`-источника. На Windows после показа окна повторно ставятся границы (смешанный DPI), topmost и `moveTop()`. Диагностика в логе: раскладка источников и дисплеев (если id пришлось чинить), `overlay shown` с границами/видимостью/topmost, первая аннотация своего стрима с состоянием оверлея.
- **Ведущий всегда знает об аннотациях.** Под переключателем в карточке LIVE — подсказка, где он увидит рисунки («поверх вашего экрана» / «в превью вашего стрима»), а пока кто-то рисует — «Имя указывает/рисует на экране» (гаснет через 4 с тишины; таймер только пока идут аннотации). Если оверлея нет (веб, Linux, окно, дисплей не определён) — кнопка «Показать» открывает превью своего стрима во всплывающем окне с рисунками.
- **Веб.** Браузер не может рисовать поверх экрана ОС и поверх других вкладок/окон — это граница платформы, не ошибка. Ведущий в вебе видит рисунки в превью своего стрима (кнопка «Показать», pop-out). Следующий шаг — Document Picture-in-Picture (только Chromium 116+): всегда-поверх окошко с превью и рисунками (docs/12).
