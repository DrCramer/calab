# ADR-0123: Умная задача — содержимое файлов, поиск дублей, отказ с причиной (2026-10-22)

**Статус: принято.** Меняет [ADR-0118](0118-smart-tasks-via-ai.md) §2 «Файлы (v1)» и «Альтернативы» (содержимое
файлов теперь передаётся). Задача CBF-75.

## Контекст
Владелец (22.10): важное бывает в файле — модель должна видеть картинки, PDF (больше одной страницы — первую и
последнюю), остальное текстом или картинкой. В настройках доски — «Искать дубли за 2 недели»: если включено,
модель сравнивает умную задачу с задачами доски за 14 дней. Модель может не заводить задачу и назвать причину
(«не хватает данных», «дубль DOC-123») — причина в окне, текст и файлы остаются, человек правит и отправляет снова.

## Решение

### 1. Файлы для модели (`internal/aifiles`)
- **Картинки** (JPEG, PNG, GIF, WebP): размеры проверяются до декодирования (≤ 20000 по стороне, ≤ 50 Мп),
  уменьшаются до 1568 px по длинной стороне, кладутся на белый фон, JPEG q82 (не влезает в остаток — меньше и
  хуже, до q50); модели — `image_url` с `data:image/jpeg;base64,…` (ссылок, которые провайдер сам скачивал бы,
  нет). HEIC и прочее — по имени.
- **PDF**: первая страница и, если страниц больше одной, последняя — картинками тем же путём; в JSON —
  `pages` (число страниц) и `shown_pages`.
- **Текст** (`text/*`, JSON, XML, YAML, CSV и текстовые расширения при `application/octet-stream`): первые
  256 КБ, валидный UTF-8 без управляющих и bidi-символов, ≤ 8000 символов на файл. docx / xlsx — по имени и
  типу (готового извлечения текста в коде нет; новый разборщик ZIP/XML — лишняя поверхность атаки).
- **Лимиты запроса**: ≤ 4 картинок (страница PDF — одна), ≤ 5 МБ их `data:` URL суммарно, ≤ 20000 символов
  текста всех файлов, картинка/PDF ≤ 25 МБ на чтение. Что не влезло — по имени с `note` (`limit`,
  `too_large`, `unreadable`, `unsupported`, `truncated`). Порядок — порядок вложений. Файлы читаются после
  проверок прав и лимитов частоты, одним разом на запрос (оба вызова модели получают одно и то же).
- **Защита процесса** (ревью безопасности): ≤ 6 картинок/PDF читаются за запрос, неудачные тоже (20
  сломанных файлов не занимают декодер 20 раз); ≤ 30 с на все файлы запроса, остальные — по имени
  (`limit`); запросы одного человека готовятся по очереди (на под), второй ждёт ≤ 30 с, затем файлы по
  имени; одна картинка декодируется за раз на под, ≤ 256 МБ памяти по цветовой модели (16-битный PNG — 8
  байт на пиксель). Файлы и вызовы модели — под общим сроком 100 с (`SmartBudget`).
- **Сообщение**: user-сообщение — массив частей: JSON данных первым, затем перед каждой картинкой подпись,
  которую пишет сервер («Image 2: file 1, page 7» — без текста из файлов). Без картинок — строка, как раньше.
- **Рендер PDF — PDFium в WebAssembly** (`github.com/klippa-app/go-pdfium` v1.21.0, MIT; PDFium BSD-3 / Apache-2.0;
  рантайм `github.com/tetratelabs/wazero` v1.12.0, Apache-2.0). Чистый Go: `CGO_ENABLED=0`, distroless static
  и Dockerfile не меняются, нового бинаря в образе нет; бинарь сервера +~8 МБ (встроенный `pdfium.wasm`
  5,8 МБ). Рантайм компилируется при первом PDF (~2 с на M-серии) и закрывается после 5 минут без PDF; один
  документ за раз, каждый в новом экземпляре модуля, без файловой системы (`FSConfig` без монтирования),
  память модуля ≤ 256 МБ, 20 с на документ (по истечении модуль убивается). Отклонены: `mutool` (AGPL),
  `pdftoppm` (GPL, цепочка библиотек, не static), cgo-PDFium (нужен libc — уход с distroless static),
  ffmpeg (PDF не читает).
- **Модель без зрения**: если провайдер отверг запрос с картинками (`bad_request`, или `model_not_found` у
  модели, прошедшей проверку), тот же шаг повторяется один раз без картинок (файлы — `note: no_images`,
  текст остаётся); задача создаётся, в ответе `files_unseen`, клиент показывает тост. Выбрано вместо ошибки:
  умная задача с файлами работает на любой модели; потеря содержимого видна человеку.
- Таймаут вызова с картинками — 45 с (без — 30 с, как было).

### 2. Поиск дублей
- `boards.ai_find_duplicates` (миграция `00015`, по умолчанию `false`), `Board.ai_find_duplicates` (в списках
  и событиях — не секрет), `UpdateBoardRequest.ai_find_duplicates` (`MANAGE_BOARD`). Переключатель — в
  карточке «Инструкция для ИИ» настроек доски.
- Если включён, после выбора доски модель получает `recent_tasks`: живые задачи этой доски с `created_at` за
  14 дней, **только видимые человеку** (`visibleTasks`: участнику с `VIEW_BOARD` — все, create-only и
  приглашённому — свои по ADR-0115), новые первыми, ≤ 30 (из ≤ 200 последних), ключ, заголовок ≤ 120, начало
  описания ≤ 300 символов одной строкой.
- С инструкцией доски — в том же втором вызове (оформление); без инструкции — отдельный короткий вызов
  «дубль ли это» (`{"duplicate_of": ""}` или отказ). Нет видимых задач за 14 дней — вызова нет.

### 3. Отказ с причиной
- Строгий JSON расширен: шаг 1 — `{"board_key","title"}` **или** `{"refuse"}`; шаг 2 — задача **или**
  `{"refuse","duplicate_of"}`; проверка дублей — `{"duplicate_of": ""}` или `{"refuse","duplicate_of"}`.
  Смешанный ответ (отказ и задача), неизвестные поля, текст вокруг — `409 AI_BAD_ANSWER`, как прежде.
- Причина: ≤ 1000 символов от модели (иначе плохой ответ), затем простой текст — без ссылок (схема `x:` и
  `www.`), без `@` (никаких упоминаний), без символов разметки Markdown/HTML, управляющих, bidi и zero-width,
  одной строкой, ≤ 300 символов; пустая после чистки — плохой ответ.
- `duplicate_of` сохраняется, только если это ключ из показанных `recent_tasks` (чужие ключи — никогда); у
  отдельной проверки дублей отказ без такого ключа — не отказ (задача создаётся).
- Ответ — `200 CreateSmartTaskResponse{refusal: {reason, duplicate_key}}` без задачи (это не ошибка
  транспорта). Окно показывает причину, кнопку «Открыть DOC-123» (обычная ссылка на задачу — откроется,
  только если человек её видит) и подсказку «поправьте и отправьте снова»; текст и файлы остаются (файлы не
  прикреплены — их можно отправить снова).

### Безопасность
- Содержимое файлов, задачи доски, инструкция и текст — недоверенные данные: в user-сообщении (JSON и
  картинки), правила — в system; итог проходит прежние проверки ADR-0118 §2 (доска только из списка, метки и
  приоритеты доски, создание путём `POST …/tasks` с правами человека). Инъекция из файла может испортить
  заголовок, описание или причину отказа, но не выйти за доски, права, метки, людей и чужие задачи.
- В логах — счётчики (файлов, картинок, задач для дублей, `files_unseen`, шаг отказа), без содержимого файлов,
  текстов задач, причины и ключа.

## Последствия
- Протокол: `Board.ai_find_duplicates`, `UpdateBoardRequest.ai_find_duplicates`, `CreateSmartTaskResponse.refusal /
  files_unseen`, `SmartTaskRefusal`; `ai.Message.Parts` (vision-части Chat Completions).
- Стоимость: картинки уходят в оба вызова (до 8 картинок на задачу); лимиты частоты ADR-0118 те же.
- Запрос — до ~100 с в худшем случае (`SmartBudget`: файлы + два вызова с картинками + повтор без них);
  таймаут чтения прокси перед api для этого пути — ≥ 120 с (docs/06).
- Независимое ревью безопасности обязательно (внешний вызов с содержимым файлов, разбор PDF в процессе API,
  задачи других людей в запросе к модели).

## Альтернативы
- **Отдать PDF провайдеру файлом** (`type: file`). Не все OpenAI-совместимые провайдеры принимают; владелец
  просил первую и последнюю страницы картинками.
- **Ошибка вместо повтора без картинок.** Модель без зрения закрывала бы умные задачи с файлами совсем.
- **Поиск дублей по всем задачам доски.** Утечка задач, которых человек не видит (create-only); отклонено.
