# ADR-0104: Комментарии к встрече (2026-10-15)

**Статус: принято.** Дополняет [ADR-0038](0038-calendar.md).

## Контекст
Владелец, 15.10: «комментарии к встрече» — обсудить повестку, оставить ссылку, договориться до и
после встречи прямо в карточке. Готовый образец — комментарии задачи (ADR-0042): это сообщения
скрытой комнаты `rooms.type = 'task'` со всем чатовым (вложения, реакции, упоминания), права
которой `perm.Resolver` выводит из прав доски.

## Решение
1. **Отдельная сущность, не скрытая комната.** `event_comments (id uuidv7, event_id → events
   ON DELETE CASCADE, author_id, body 1..4000, created_at, edited_at)`, миграция 00099. Видимость
   встречи — правило календаря (`calendar.viewer.sees`: организатор, участник, видящий комнату;
   гостям календарь закрыт; «Занято» из free/busy встречу не раскрывает), а не права комнаты:
   скрытая комната потребовала бы нового типа в `perm.Resolver` (путь безопасности), исключений
   в выборках комнат/тарифа/поиска/push (≈ 10 мест на сервере и ≈ 10 на клиенте) и
   ре-вычисления видимости встречи внутри резолвера. Нужное владельцу — текст, правка,
   удаление, счётчик, realtime — помещается в одну таблицу и пять маршрутов. Вложения, реакции
   и упоминания — не в v1.
2. **Уровень — встреча (серия целиком).** Правка серии в v1 меняет все вхождения (ADR-0038 §1),
   повестка регулярной встречи живёт поверх вхождений; карточка вхождения показывает комментарии
   серии. Вхождение можно добавить позже nullable-колонкой `occurrence_at`.
3. **Права (сервер).** Читать и писать — кто видит встречу (`viewer.sees`); иначе 404, гостю —
   403. Править — только автор. Удалять — автор или тот, кто может менять встречу
   (`viewer.canEdit`: организатор, `MANAGE_ROOM` в комнате, `MANAGE_EVENTS`; администратор — через
   свои биты). Отменённая встреча: комментарии читаются и удаляются, новые и правка — 404. Боты —
   `botDeny` на всех маршрутах (v1). Лимит записи — отдельный `rl:event-comment:` (20 сразу,
   20 в минуту), не съедает бюджет правок встречи.
4. **API.** `GET /api/events/{id}/comments?before=<id>&limit=` (новейшие `limit` ≤ 100, по
   возрастанию, `has_more`), `POST` → 201, `PATCH /api/events/{id}/comments/{comment_id}`,
   `DELETE …/{comment_id}` → 204. Текст обрезается по краям, markdown-lite как описание.
   `CalendarEventCounts.comments` — число комментариев (в списках и событиях; гостю 0).
5. **Realtime.** `EVENT_COMMENT_UPSERT { workspace_id, event_id, comment, comments }` и
   `EVENT_COMMENT_DELETE { workspace_id, event_id, comment_id, comments }` по каналу пространства;
   `gateway.routeEventComment` доставляет их тем же, кому `EVENT_UPDATE` (организатор, участники,
   видящие комнату), без гостей и ботов; поля маршрутизации (`room_id`, `organizer_id`,
   `attendee_ids`) шлюз стирает перед отправкой.
6. **Уведомления — не в v1.** У задач уведомления о комментариях — отдельная модель
   (`TaskNotice`, подписки, уровни, push, ретрансляция боту — ADR-0089/0090); повторять её для
   встреч — отдельная задача (docs/12). Пока комментарий виден в открытой карточке сразу, а
   число — на карточке встречи.
7. **Клиент.** Секция «Комментарии — N» в карточке встречи (`EventCard`): строки — аватар 20, имя,
   время, текст markdown-lite, «изменено»; меню «…» своей строки — «Изменить» / «Удалить»,
   организатору — «Удалить» у чужих; поле ввода внизу (Enter — отправить, Shift+Enter — перенос).
   Гостю комнаты секции нет.
