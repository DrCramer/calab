# ADR-0124: Переадресация группы, если никто не ответил — по умолчанию выключена (2026-10-22)

**Статус: принято (22.10), реализовано (CBF-72, ветка `cbf-72-group-fallback`).** Меняет поведение групп из
[ADR-0117](0117-sip-inbound-ivr.md) §3–§4 (`ring_sec`, `on_fail`, «один круг» у очереди); поток входящего
вызова, машина состояний (`internal/sip/machine.go`), воркер и права — те же. Касается обоих путей входящих
(на наш адрес — ADR-0117, по регистрации — [ADR-0121](0121-sip-inbound-registration.md)): после LiveKit SIP
они одинаковы, группа как цель (точка входа, кнопка меню, «нет нажатия», переадресация другой группы, номер
группы) всегда проходит через `Route` / `InCall.Enter`.

## Контекст

Слова владельца (22.10): у группы (например 1001) — необязательная переадресация. **По умолчанию выключена:**
группа звонит, пока кто-нибудь не ответит или звонящий не положит трубку. **Включена:** таймаут N секунд и
действие — перевести в другую группу, на сотрудника, на бота или положить трубку. Настраивается в группе.

Было (ADR-0117): «все сразу» звонит `ring_sec` (10–60 с, по умолчанию 30), «по очереди» — один круг по
`member_ring_sec`, затем всегда `on_fail` (по умолчанию «положить трубку»). То есть звонок в группу без
настройки обрывался через 30 с — ровно то, чего владелец не хочет.

## Решение

1. **Модель** (миграция `00016_sip_group_fallback.sql`): `sip_groups.fallback_enabled bool` (false) и
   `fallback_sec int` (30; 5–600). Действие — существующие `on_fail_*` (тот же набор, что везде в маршрутах:
   положить трубку, меню, сотрудник/бот — номер `extension`, группа; `REPEAT` нельзя). При выключенной
   переадресации `on_fail_*` хранится, но не используется (включил обратно — действие на месте).
   `ring_sec` больше не используется (поле в API оставлено ради совместимости, проверка диапазона — прежняя).
   Существующие группы: `on_fail` ≠ «положить трубку» → переадресация включена со временем, которое было
   (`ring_sec` у «все сразу», `member_ring_sec × участники` — один круг — у «по очереди»); группы с «положить
   трубку» становятся «звонит до ответа» — значение владельца по умолчанию.
2. **Выключена** — группа звонит до ответа или отбоя звонящего:
   - «все сразу»: звонят все доступные; раз в 15 с (`ringRecheck`) группа добавляет освободившихся (не
     занятых другим звонком); кто нажал «Отклонить», больше не звонит; отклонили все, кто мог ответить, —
     звонок завершается (`declined`);
   - «по очереди»: круг за кругом по `member_ring_sec`, каждый новый круг — с актуальной доступностью;
     указатель round-robin двигается только по итогу звонка (как раньше);
   - все участники заняты (или, по очереди, не в сети) — звонящий слышит гудок, группа ждёт и проверяет раз
     в 15 с; в группе нет ни одного человека/бота — сразу конец (`no_members`).
   Верхняя граница — та же, что у любого входящего: `max_call_duration` транка 2 ч и метёлка (ADR-0117 §4.4).
3. **Включена** — через `fallback_sec` с момента, когда группа начала звонить, звонок уходит по действию;
   до этого «все сразу» звонит, «по очереди» идёт кругами (звонок участнику обрезается моментом переадресации).
   Сразу (без ожидания) — если звонить некому (пусто, все заняты / не в сети) или отклонили все.
4. **Петли** (A → B → A): **ограничение в рантайме, не проверка при сохранении.** Не больше
   `MaxFallbacks = 3` переадресаций групп за один звонок (`InCall.Fallbacks`, считаются и мгновенные внутри
   `Route`); следующая — конец с причиной `loop`. Старый общий предел `MaxHops = 10` переходов остаётся.
   Почему не валидация графа: цепочка может идти через меню и номера, удаление цели (`ON DELETE SET NULL`) и
   правка другой группы меняют граф без сохранения этой группы, а A ↔ B с таймаутами — осмысленная настройка
   («дневная смена ↔ ночная»), которой нужен лишь предел. При сохранении отклоняется только переадресация
   **на саму группу или её собственный номер** (`422 onFail`) — она бессмысленна (те же люди ещё раз).
5. **Сервер**: цель — только объект этого пространства (`parseTarget` + составные FK `(workspace_id, …)`);
   права — как на правку группы сегодня (`MANAGE_INTEGRATIONS`, не гость, тариф с телефонией; боты —
   `botAllow`). API: `SipGroup.fallback_enabled/fallback_sec`, те же поля в `Create/UpdateSipGroupRequest`
   (`422 fallbackSec`). Пустые переходы машины (проверка «кто освободился» ничего не нашла) не пишут журнал и
   не шлют `SIP_CALL_UPDATE`.
6. **Клиент** (docs/08 «Телефония»): в форме группы — секунды только у «по очереди» («Каждому N с»); блок
   «Переадресация, если никто не ответил» — переключатель с подсказкой (выкл.: «группа звонит, пока
   кто-нибудь не ответит…»; вкл.: «не больше трёх переадресаций между группами…»), при включении строка
   «Через [N] с перевести [куда]» (тот же выбор цели, без самой группы). В строке группы — «переадресация через
   N с»; ⚠ удалённой цели — только при включённой переадресации.

## Последствия

- Звонок в группу без настройки больше не обрывается через 30 с; абонент может ждать долго (до 2 ч) — это
  желание владельца, тарификация у абонента идёт (ADR-0117 «Последствия»).
- Тик входящих (5 с) делает переход по живому звонку группы раз в 15 с: чтение станции из Postgres на звонок
  (≤ 5 живых входящих на пространство) — пренебрежимо.
- Проверено только тестами (unit машины и маршрута, интеграционные API и входящий звонок с переадресацией);
  настоящий звонок через Plusofon — только на проде.
