# ADR-0115: «Создавать задачи» без «Видеть доску» — создаёт и видит только свои карточки (2026-10-22)

**Статус: принято.** Уточняет [ADR-0042](0042-boards.md) (`ComputeBoard`: «без `VIEW_BOARD` — ничего»),
[ADR-0059](0059-task-scoped-access.md) и [ADR-0076](0076-task-watchers.md) (доступ по карточкам: четвёртое
основание — автор), [ADR-0111](0111-bot-acts-for-consenting-member.md) («от имени» — права участника). Задача CBF-61.

## Контекст
Владелец (22.10): на закрытой доске (DOC / INV / HR) сотрудник должен заводить задачи — сам или через бота
от своего имени — и видеть только свои карточки, не всю доску. В «Доступе» связку «Создавать задачи» ✓ +
«Видеть доску» не дано поставить можно, но `ComputeBoard` без `VIEW_BOARD` возвращал 0 → `POST …/tasks` 403
`CREATE_TASKS required`, в том числе «от имени» с согласием.

## Решение
1. **Правило (одно, Go/TS зеркально).** `perm.ComputeBoard` / `computePermissions({board})`: если после
   переопределений `VIEW_BOARD` нет, результат — `CREATE_TASKS`, когда его дало **переопределение доски** (роли
   или личное, по тому же порядку: младшая роль → старшая → пользователь) и позже его никто не запретил; иначе 0.
   `CREATE_TASKS` из ролей пространства не считается — иначе каждый участник создавал бы на каждой приватной
   доске. `EDIT_TASKS` / `MANAGE_BOARD` без `VIEW_BOARD` отбрасываются. Гость — 0. `perm.CreateOnly(bits)` =
   `bits == CREATE_TASKS`. Векторы — `proto/testdata/permissions.json` (`board: create-only …`).
2. **Кто.** Только человек с ролью не `guest` на живой доске (`perm.Resolver`: `taskScoped`; боту и гостю биты
   обнуляются — бот без `VIEW_BOARD` по-прежнему не видит доску, ADR-0042 §2). Такой участник —
   `BoardAccess.TaskScoped` даже без единой карточки, `Bits = CREATE_TASKS`.
3. **Что видит.** Доску в списке (`task_scoped = true`, `permissions = CREATE_TASKS`, без переопределений и
   `open_tasks`) и только свои живые карточки: автор (`tasks.created_by`), исполнитель, согласующий,
   наблюдатель. `perm.TaskBits(acc, assignee, approver, watcher, author)`: автор считается **только** у
   create-only (участник по карточкам, когда-то написавший задачу, её через авторство не видит); автор и
   исполнитель — `VIEW_BOARD | CREATE_TASKS` (правит свою, как участник по карточке), согласующий и
   наблюдатель — `VIEW_BOARD`. Чужие — 404. Список, поиск, «Мои задачи», профиль (`VisibleBoards.CreateOnly`,
   `ListInvitedTasks.author_boards`), уведомления (`boards.sees` → `taskBitsOf`), комната задачи, шлюз
   (`invAuthor` в карте приглашённых, в счётчик `scoped` не входит) — по этому же правилу.
4. **Что может.** `POST /api/boards/{id}/tasks` — 201 (родитель и `afterTaskId` — только среди видимых ему
   задач, иначе 422); «от имени» (ADR-0111) — так же, автор — участник. Журнал, настройки, доступ, виды
   (правка), лейблы «на лету», перенос — 403, как участнику по карточкам. Архивировать свою — можно (как автор с
   `CREATE_TASKS`), после чего она скрыта.
5. **Клиент.** Связка в редакторе доступа подписана «Создаёт и видит только свои карточки» (`boards.perm.createOnly`,
   четыре локали): `CREATE_TASKS` ✓ и `VIEW_BOARD` ✕, или нейтрален на приватной доске. «+ Задача», `C`, «Задача из
   сообщения» берут `CREATE_TASKS` из `permissions` — работают; права карточки — `taskPermissions(board, task, me)` с
   `createdBy`.

## Последствия
- Новых таблиц, битов, миграций и полей протокола нет; в SQL — `is_bot` в `GetBoardAccess`, `created_by` в
  `GetTaskRoomRef`, автор в `ListWorkspaceTaskInvitees`, `author_boards` в `ListInvitedTasks`.
- Карта приглашённых шлюза получает запись на каждую живую задачу (автор) — память ~ число задач пространства.
- Переход «по приглашению ↔ create-only» в шлюзе — `BOARD_DELETE` + `BOARD_CREATE` (у клиента меняется набор задач).
- Изменение прав: второе независимое ревью безопасности обязательно (пути видимости, боты, «от имени»).

## Альтернативы
- **Новый бит `VIEW_OWN_TASKS`.** Ещё один бит в UI и матрице, хотя связка уже есть в интерфейсе; отклонено.
- **Считать и `CREATE_TASKS` ролей пространства.** Открыло бы создание на всех приватных досках; отклонено.
