# ADR-0129: Автоответ — нажатие во время записи, набор добавочного номера, номер без внешних звонков (2026-10-23)

**Статус: принято (23.10, CBF-79, CBF-80).** Дополняет [ADR-0117](0117-sip-inbound-ivr.md) (входящие,
меню, машина состояний), отменяет его решение «нажатие во время подсказки не прерывает её» (шаг 1) и
пункт §9 «набор внутреннего номера с телефона — следом».

## Контекст

- **CBF-79 (баг).** Пока играет запись меню, нажатия теряются: `InCall.Digit` отбрасывал цифру, если
  воркер ещё не прислал `played` и не прошла длительность записи. Звонящие, знающие меню, жмут сразу.
- **CBF-80.** Владелец: в меню — галочка «Разрешить набор добавочного номера» (звонящий набирает
  внутренний номер человека, бота или группы); у номера участника — «Не принимать внешние звонки по
  добавочному» («запретить подключаться через добавочный номер внешних»); в профиле участника — его
  внутренний и мобильный номер.

Как DTMF доходит: `livekit/sip` разбирает RFC 2833 / SIP INFO и публикует в комнату data-пакет
`SipDTMF`; воркер `calab-ivr` получает его в `OnDataPacket` независимо от того, что сам играет, и шлёт
API `dtmf`. Значит, нажатия терялись не в воркере и не в LiveKit, а в машине состояний API — там и
правим. Нажатия до входа воркера в комнату LiveKit никому не доставляет (data-пакеты не хранятся) —
это доли секунды до начала записи, не лечим.

## Решение

1. **Barge-in.** Цифра в фазе меню считается всегда: во время записи, до её начала (воркер ещё
   скачивает файл), после. Первая цифра ввода останавливает запись (`stop` воркеру; `Played = true`,
   поздний `played` уже не двигает дедлайн). Цифры, пришедшие до входа в точку маршрута (состояние
   сохранено, `Enter` ещё не выполнен), копятся в `InCall.Early` (≤ 6) и применяются, если точка — меню.
2. **Сбор цифр** — чистая функция `sip.Collect(menu, pbx, digits, end)` (табличные тесты):
   - набор выключен — цифра сразу кнопка меню (кнопка без пункта — как раньше, «нет ввода»);
   - набор включён: цифры копятся в `InCall.Digits`, пауза между цифрами **3 с** (`InterDigit`), `#`
     или `*` заканчивают ввод (пустой ввод + `#`/`*` — это кнопка), 6 цифр — тоже конец;
   - полный номер, с которого не начинается более длинный, — соединяем сразу; одна цифра — кнопка
     меню, с которой не начинается ни один номер, — сразу кнопка; строка, с которой не начинается ни
     один номер и которая не кнопка, — сразу «не найдено»; иначе ждём паузу; по паузе: точный номер →
     соединяем, одна цифра-кнопка → кнопка, иначе «не найдено».
   - Пауза 3 с короче общего тика 5 с: реплика, принявшая цифру, ставит `time.AfterFunc` на дедлайн
     (тот же `expireCall`, что у тика, под блокировкой звонка); тик подхватит, если реплика ушла.
3. **Что можно набрать**: номер группы; номер человека/бота, за которым кто-то есть и который не
   закрыт для внешних. Неназначенный номер (повесил бы трубку) и закрытый — **«не найдено»**, их не
   отличить от несуществующего.
4. **«Не найдено»** = кнопка без пункта: меню звучит снова (попытка +1), после `repeats` — «Если ничего
   не нажали». Выбрано вместо отдельной ветки: повтор меню звонящий понимает, новая настройка не нужна.
   В журнале маршрута — `dial:<цифры>`.
5. **Набранный номер** идёт как маршрут `extension` (группа — как группа): занят — тот же `busy`, что у
   кнопки на этого человека; 30 с без ответа — трубка (как прямой номер из меню).
6. **«Не принимать внешние звонки по добавочному»** (`sip_extensions.external_blocked`, только номера
   людей и ботов; у номера группы — 422 `externalBlocked`, CHECK в БД). Закрывает только **набор номера
   внешним звонящим** из меню. Маршруты, которые настроил админ (кнопка меню, точка входа, переадресация
   группы), и членство в группах продолжают звонить: это осознанное решение админа, а владелец просил
   закрыть именно «подключение через добавочный». Внутренние звонки этим флагом не затронуты.
   Проверка — на сервере (в `Collect` по снимку станции), клиент только показывает переключатель.
7. **Профиль**: карточка участника и «Профиль» показывают «Внутренний номер» (`WorkspaceMember.extension`;
   гостям сервер его не отдаёт — `pbconv.ExtensionVisible`) рядом с почтой и телефоном; мобильный —
   уже существующее `User.phone` (ADR-0077, видно только коллегам), правила видимости не меняются.

Данные: миграция `00120_sip_extension_dialing.sql` — `sip_ivr_menus.dial_extensions bool default false`,
`sip_extensions.external_blocked bool default false`. Протокол: `SipIvrMenu.dial_extensions`,
`SipExtension.external_blocked` (+ поля в Create/Update).

## Почему не иначе

- **Останавливать запись в воркере по DTMF сам** — экономит один круг воркер → API → воркер (~100 мс),
  но размазывает логику меню по двум процессам (при наборе с выключенной опцией кнопка без пункта всё
  равно перезапускает запись). Голова остаётся в API (ADR-0117 §2).
- **Отдельная цель «не найдено» (короткий сигнал / свой маршрут)** — новая настройка и запись; повтор
  меню закрывает задачу.
- **Закрыть человека и для маршрутов админа** — ломает схемы «кнопка 2 → директор», которые админ
  настроил сам; для этого есть удаление кнопки.
