# ADR-0109: Бот с правами может то же, что человек с этими правами (2026-10-19)

**Статус: принято.** Меняет решения [ADR-0031](0031-bots.md) §2 (закрытые «на всякий случай» маршруты),
[ADR-0051](0051-bot-api-v2.md) §5 (список «остаются закрыты») и [ADR-0060](0060-board-automations.md) §3–§4 (правила
и Git-связи — только люди); уточняет [ADR-0035](0035-camera-background.md), [ADR-0050](0050-workspace-apps.md),
[ADR-0061](0061-achievements.md), [ADR-0104](0104-event-comments.md) в части ботов. [ADR-0106](0106-bot-acts-as-owner.md)
(«от имени владельца») и [ADR-0108](0108-approval-override-and-on-behalf.md) (согласование — только человек) **не
меняются**.

## Контекст
Задача CBF-11 с бага-доски, владелец: «если мы боту права дали управлять, он должен иметь возможность всё делать».
Около 220 маршрутов были `botDeny` независимо от ролей бота: например, бот с `MANAGE_BOARD` и
`MANAGE_INTEGRATIONS` не мог создать правило автоматизации или подключить Git к доске (`403 BOT_NOT_ALLOWED`).
Часть закрытий была осознанной (аккаунт, деньги, управление ботами), часть — «на всякий случай» при запуске фичи.
Таблица в `internal/app/botroutes.go` была плоской картой с разрозненными комментариями, и причину закрытия
приходилось искать по ADR.

## Решение

### 1. Принцип
Бот — пользователь, права — только роли и переопределения (ADR-0031 §1 без изменений; `computePermissions` /
`perm.*` не трогаем). **Маршрут, который обработчик охраняет правом, — `botAllow`**: бот получает ровно то, что
участник с теми же ролями; без бита — обычный `403` обработчика с названием права, не `BOT_NOT_ALLOWED`.
`botDeny` остаётся только там, где роль не может быть ответом (§2).

### 2. Что остаётся закрыто и почему (`botDeny`, группы таблицы)
| Группа | Почему |
|---|---|
| Аккаунт: сессии, пароль, почта и подтверждение, push-устройства, выбор username | у бота нет пароля, почты, сессий; вход — только токен |
| Identity: SSO, каталог, OAuth-клиенты и согласия, OIDC-провайдер, повторный вход | вход человека и политика входа пространства (ADR-0054, ADR-0102) |
| Оплата и суперадминка | деньги — решение владельца (ADR-0080; роли и так не дают ботам `BILLING_*`) |
| Владение и членство: создать / удалить / найти / вступить в пространство, вход по коду, «забрать себе» (take-over) | бот не владеет пространством и не вступает сам — его добавляют люди; take-over — владельца (ADR-0078) |
| Аккаунты без согласия: `invites/lookup`, `POST …/members` | перебор адресов, добавление без согласия (ADR-0051 §5) |
| Управление ботами и надзор за ними: создание, токены, аватары, `acts_as_owner`, карточка `GET /api/bots/{ref}`, журнал контактов, отданных ботам, блокировки ботов | нет самоэскалации и надзора бота за ботами (ADR-0031, ADR-0048, ADR-0100, ADR-0106) |
| Решение человека: голос в согласовании, нажатие кнопки, передача контакта, RSVP | намерение конкретного человека (ADR-0049, ADR-0100, ADR-0108); «от имени» открыт только голос (ADR-0106) |
| Личное: заметки, статус, настройки уведомлений и списка чатов, дни рождения (таблица и установка), «сегодня», CalDAV и внешние календари | личные данные и настройки человека (ADR-0039, ADR-0045) |
| Голос и гости: звонки один на один, гостевые ссылки комнат, ожидание впуска | бот не звонит людям (ADR-0034 §7); гостевая ссылка — анонимный вход посторонних в звонок, его бот не выдаёт (ADR-0031; так же временные комнаты и встречи бота) |
| Служебное: превью ссылок, конвертер HEIC | помощники клиента, не API: токен не должен становиться бесплатным прокси / CPU |

### 3. Что открыто (`botDeny` → `botAllow`), бит — тот же, что у человека
| Маршруты | Право |
|---|---|
| `POST /api/boards/{id}/rules`, `PATCH · DELETE /api/rules/{id}`, `POST /api/rules/{id}/test` | `MANAGE_BOARD` доски (+ тариф) |
| `GET · PUT · DELETE /api/boards/{id}/git` | `MANAGE_BOARD` + `MANAGE_INTEGRATIONS` ws |
| `GET · PUT · DELETE /api/boards/{id}/webhook`, `POST …/webhook/ping` | `MANAGE_BOARD` (чтение), + `MANAGE_INTEGRATIONS` (изменение), тариф |
| `PUT /api/boards/{id}/permissions` | `MANAGE_BOARD`; не-админ выдаёт только свои биты (как комнаты, они уже были `botAllow`) |
| `/api/workspaces/{id}/apps`, `/api/workspace-apps/{appId}…` | список — участник; изменение — `MANAGE_INTEGRATIONS`. В READY ботам приложения по-прежнему не отдаются |
| `/api/workspaces/{id}/integrations/gptunnel` | просмотр — не гость; подключить / отключить — `MANAGE_INTEGRATIONS` |
| `GET · PUT /api/workspaces/{id}/sip`, `POST …/sip/test` | `MANAGE_INTEGRATIONS` (пароль провайдера не отдаётся) |
| `GET /api/workspaces/{id}/calls` | `VIEW_JOURNALS` |
| `/api/workspaces/{id}/backgrounds…` | список — участник; изменение — `MANAGE_WORKSPACE`, картинка — своя загрузка |
| Каталог достижений `POST …/achievements`, `PATCH · DELETE /api/achievements/{id}`; выдача / отзыв | `MANAGE_WORKSPACE`; `MANAGE_MEMBERS` (не боту и не себе) |
| `POST /api/rooms/{id}/make-permanent` | `MANAGE_ROOM` ws |
| `POST /api/rooms/{id}/recordings/{rid}/recheck`, `…/reupload`, `DELETE …/recordings/{rid}` | как у людей (`participant`: бот ещё `MANAGE_RECORDINGS`, ADR-0051 §4); удаление — кто начал, `MANAGE_MESSAGES` комнаты или `MANAGE_RECORDINGS` |
| `/api/events/{id}/comments…` | кто видит встречу; правит автор; удаляет автор или `canEdit`. Gateway комментариев ботам по-прежнему не шлёт (ADR-0104 §5) |

Обработчики проверены: у каждого — своя проверка права; единственной защитой `botDeny` был только у трёх, где
стоял явный отказ ботам (`repoBoard`, `webhookBoard`, `setPermissions` в `internal/boards`) — отказ убран, проверки
битов остались. Запрет ботам в `listContactShares` (журнал контактов) остаётся — маршрут закрыт (§2).

### 4. «От имени владельца» не расширяется
Открытые этим ADR маршруты помечены `onBehalfClosed`: запрос с `Calab-On-Behalf: owner` на них — `403
ON_BEHALF_ROUTE`, как и раньше. Набор маршрутов «от имени» (ADR-0106 §3) не меняется; расширить его — отдельное
решение строкой таблицы.

### 5. Таблица — по группам с причиной
`botRoutes` теперь строится из `botRouteGroups`: секции `{access, why, onBehalf?, routes}`. У каждой секции `why`
(для `botDeny` — причина, которую роль не снимает; для `botAllow` — что проверяет обработчик). Тесты:
`TestBotRouteGroups` (у каждой секции есть причина, `onBehalf` только у `botAllow`, секции ADR-0109 закрыты «от
имени»), дубликат маршрута — паника при инициализации; `TestBotRouteTable` / `TestOnBehalfRouteTable` — как
раньше. `tools/gen-bot-routes.ts` читает новые секции (`_routes.json` не меняет формат). Административные
изменения открытых маршрутов добавлены в `botAudited` (строка `bot action` с владельцем бота).

## Последствия
- Безопасность: токен бота с `MANAGE_INTEGRATIONS` теперь может подключить Git / вебхук доски (секрет — в ответе),
  сменить SIP-транк (звонки за счёт пространства), привязать GPTunneL к своему аккаунту (записи встреч уйдут туда),
  добавить веб-приложение (ссылка у всех участников); с `MANAGE_BOARD` — правила, действующие без проверки прав
  автора (ADR-0060 §2), и доступ к доске в пределах своих битов. Это ровно права человека с теми же битами; UI уже
  предупреждает при выдаче административных битов роли с ботами (ADR-0051). Журнал `bot action` пишет эти действия.
  Второе ревью обязательно (CLAUDE.md п. 6).
- Интеграционные тесты: `bot_api_v3_integration_test.go` — по представителю каждой открытой группы с битом (2xx) и
  без (403 обработчика, не `BOT_NOT_ALLOWED`); старые тесты, ожидавшие `BOT_NOT_ALLOWED`, переписаны.
- Документация: docs/16, docs/04, лендинг (`bots/auth`, `index`, `rest-boards`, `rest-members`, `rest-rooms`,
  `rest-calendar`, `rest-messages`, `webhooks`, `changelog`, `reference/routes`), proto-комментарии.

## Альтернативы
- **Точечно открыть только правила и Git.** Закрывает жалобу, но оставляет ту же несогласованность в соседних
  маршрутах (вебхук доски, интеграции, достижения) и плоскую таблицу без причин.
- **Отдельные бот-биты («бот может администрировать интеграции»).** Права не должны зависеть от того, бот ли
  субъект (ADR-0031 §1); второй набор битов удвоил бы матрицу прав.
- **Открыть и гостевые ссылки комнат.** Отложено: это анонимный вход посторонних в звонок, и на нём же стоят
  временные комнаты и встречи бота (ADR-0044, ADR-0051 §3) — менять вместе, отдельным решением.
